## 2. 기능 요구사항과 인수 기준

사용자 구분은 00-context §2를 따른다.
- 인수 기준(AC)은 시연이나 실행에서 **눈으로 확인할 수 있는 결과**로 적는다.
- 판정은 5절의 시나리오 체크리스트로 한다.

| R-ID | 요구사항 | 사용자 | 조건·입력 | 기대 출력 | 오류 상황 → 동작 | 인수 기준 (AC) | 우선 |
|---|---|---|---|---|---|---|---|
| R-01 | 하나의 화면에서 업무 지식 탐색 | 일반 구성원, 심사자 | 가상 데이터가 로드된 유니버스에서 노드 선택 | 관련 정보와 연결된 노드가 펼쳐짐 | 연결 없음 → "연결 없음" 표시, 화면은 멈추지 않음 | ① 노드를 클릭하면 속성과 연결 노드가 같은 화면에 표시된다. ② 연결이 없는 노드를 클릭하면 "연결 없음"이 표시되고 계속 조작할 수 있다 | P0 |

## 8. 위험 (이번 변경으로 생김)

- **K-1** (RQ-5 결정으로 대응됨, 2026-09-30):
  - 내용: 심사위원이 직접 실행하면 규칙 기반 결과만 보게 되어, 영상과 실행 결과가 다르게 보일 수 있다.
  - 대응:
    - 화면에 생성 방식(LLM/규칙)을 표시한다(R-15).
    - 실행 안내에 "키를 설정하면 LLM으로 동작한다"고 적는다.
  - 재검토 조건: 주최 측이 키가 들어간 제출물을 요구하거나 허용할 때.
- **K-2** (새 위험):
  - 내용: Claude API 비용 부담 주체가 **미확인**이고, 크레딧이 없으면 영상 촬영 전에 LLM 동작을 검증할 수 없다.
  - 대응: 크레딧 충전을 영상 촬영의 준비 조건으로 3단계에 넣는다.
  - 재검토 조건: 크레딧을 준비할 수 없으면 RQ-5의 대안 ①(외부 API 전면 생략)으로 되돌린다.
- **K-10~K-13** (CR-10으로 생김, 2026-10-04): 늦게 넣은 기능의 회귀(K-10), 조력자 의견 지연으로 A를 못 정함(K-11. D의 실문서 미확보는 T-21 선행 조건), 표 입력과 기존 편집 화면의 혼동(K-12), 실제 문서에 민감정보가 섞임(K-13). 대응과 재계획 조건은 03-plan 4절.
