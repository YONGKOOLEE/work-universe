## 1. 우선순위 구분 (사용자 승인 "승인", 2026-09-30)

v0.2 §12-3에 따르면, 1차 제출물의 구현 수준이 확인되면 우선순위를 다시 본다. 구현 수준은 아직 미확인이므로, 30일 기한과 v0.2의 MVP 정의를 기준으로 아래처럼 나눈다.

| 구분 | 의미 | R-ID |
|---|---|---|
| **P0 MVP** | 종단 흐름(탐색 → 자료 1건 추가 → 인수인계 초안 → 인사이트 1건)에 꼭 필요함 | R-01, R-02, R-03, R-04, R-05(인사이트 1종), R-06, R-13 |
| **P1 1차 제출 필수** | 1차 제출 전에 완료해야 함 | R-12, R-11(v0.2 "필수"), R-05(나머지 인사이트), R-07, R-08, R-10, R-14, R-15(연결부·사전 생성·문서 변환. CR-1·CR-5. 〔D〕 CR-10으로 변환 규칙 v2 포함), R-16〔A〕, R-17〔B〕, R-18〔C〕, R-09(문서만)〔E〕, R-19〔A〕, R-20〔B〕, R-21〔C〕, R-22〔D〕(R-19~R-22는 CR-12). CR-10·CR-12 항목은 일정이 부족하면 먼저 뺀다(03-plan 3절) |
| **P2 후순위** | 1차 제출 이후 또는 여유가 있을 때 | R-15의 Claude API·사내 LLM 연결(CR-1). R-09는 CR-10으로 P1(문서만)이 됨. R-09 문서가 다루는 확장 구현(서버·로그인·권한·여러 사람·사내 LLM)은 1차 제출에 넣지 않는다 |

## 2. 기능 요구사항과 인수 기준

사용자 구분은 00-context §2를 따른다.
- 인수 기준(AC)은 시연이나 실행에서 **눈으로 확인할 수 있는 결과**로 적는다.
- 판정은 5절의 시나리오 체크리스트로 한다.

| R-ID | 요구사항 | 사용자 | 조건·입력 | 기대 출력 | 오류 상황 → 동작 | 인수 기준 (AC) | 우선 |
|---|---|---|---|---|---|---|---|
| R-01 | 하나의 화면에서 업무 지식 탐색 | 일반 구성원, 심사자 | 가상 데이터가 로드된 유니버스에서 노드 선택 | 관련 정보와 연결된 노드가 펼쳐짐 | 연결 없음 → "연결 없음" 표시, 화면은 멈추지 않음 | ① 노드를 클릭하면 속성과 연결 노드가 같은 화면에 표시된다. ② 연결이 없는 노드를 클릭하면 "연결 없음"이 표시되고 계속 조작할 수 있다 | P0 |
| R-02 | 유니버스에 자료 추가·수정 | 일반 구성원 | 사용자가 자료를 입력하거나 변경 | 저장 후 그래프와 탐색 화면에 반영됨 | 필수 정보 누락이나 중복 → 저장 거부, 사유 표시 | ① 추가한 노드가 저장 직후 그래프에 보인다. ② 수정 전 값이 이력으로 남는다 [1단계 제안]. ③ 필수값을 비우면 저장되지 않고 사유가 표시된다. ④ 중복 입력 시 사유가 표시된다(중복 판정 기준은 2단계에서 정함) | P0 |

| R-04 | LLM 없이도 초안 생성 유지 | 심사자(키 없는 실행), 일반 구성원 | LLM 미연결(키 없음) 또는 호출 실패 | 규칙 기반 초안이 생성되고, 생성 방식(LLM/규칙)이 표시됨 | 대체 동작도 실패 → 원인 표시 | ① 키 없이 실행해도 R-03의 AC ①②를 충족한다. ② 화면에 생성 방식이 보인다. ③ LLM 호출 실패를 흉내 내면 규칙 기반으로 전환된다 | P0 |

## 3. 범위 구분

- **범위 밖** (v0.2 §5 유지):
  - 실제 사내 시스템·데이터 연동
  - 조직관리 유니버스의 기준 데이터 검증 역할(R-09 문서로만 다룸)
  - 효과 수치의 확정
  - 인력배치 등 의사결정 자동화
  - 모바일 앱(00-context, 2026-09-30)
- **사람의 최종 판단 영역** (v0.2 §6):
  - 인수인계 문서 확정(R-03)
  - 인사이트 해석·활용과 인력배치(R-05)
  - 서로 다른 유니버스 간 업무 동일성 연결(R-11)
- **LLM의 역할** [사용자 확인 "전부다", 2026-09-30]: LLM은 위 판단을 대신하지 않고, 근거 노드에 기반한 문장 작성과 후보 제시만 한다.
  - (a) 인수인계 초안 문장화(R-03)
  - (b) 인사이트 결과의 자연어 설명(R-05)
  - (c) 업무 동일성 후보 제시(R-11)
  - 세 역할 모두 LLM이 없으면 규칙 기반으로 대체된다(R-04의 원칙을 확장).
  - 계산 자체(밀집/공백 집계, 유사도 등)는 LLM 없이 그래프 통계로 한다.
- **LLM 연결 방식** [사용자 결정 "2번으로 진행", 2026-09-30]:
  - 용어: 이 문서의 "외부 API"는 **Claude API**를 뜻한다. 사내 LLM과 구분하려고 "외부"라고 불렀다.

## 8. 위험 (이번 변경으로 생김)

- **K-1** (RQ-5 결정으로 대응됨, 2026-09-30):
  - 내용: 심사위원이 직접 실행하면 규칙 기반 결과만 보게 되어, 영상과 실행 결과가 다르게 보일 수 있다.
  - 대응:
    - 화면에 생성 방식(LLM/규칙)을 표시한다(R-15).
    - 실행 안내에 "키를 설정하면 LLM으로 동작한다"고 적는다.
  - 재검토 조건: 주최 측이 키가 들어간 제출물을 요구하거나 허용할 때.
- **K-2** (새 위험):
  - 내용: Claude API 비용 부담 주체가 **미확인**이고, 크레딧이 없으면 영상 촬영 전에 LLM 동작을 검증할 수 없다.
  - 대응: 크레딧 충전을 영상 촬영의 준비 조건으로 3단계에 넣는다.
  - 재검토 조건: 크레딧을 준비할 수 없으면 RQ-5의 대안 ①(외부 API 전면 생략)으로 되돌린다.
- **K-10~K-13** (CR-10으로 생김, 2026-10-04): 늦게 넣은 기능의 회귀(K-10), 조력자 의견 지연으로 A를 못 정함(K-11. D의 실문서 미확보는 T-21 선행 조건), 표 입력과 기존 편집 화면의 혼동(K-12), 실제 문서에 민감정보가 섞임(K-13). 대응과 재계획 조건은 03-plan 4절.
