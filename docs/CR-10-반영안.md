# CR-10 반영안 — 승인되면 01·02·03·limits에 그대로 붙여 넣을 문구

- 문서: CR-10 반영안 v0.1 · 상태: **approved(2026-10-04 "우선 전부 권장대로") · 01·02·03·limits에 반영함** · 작성 2026-10-04
- 근거: `docs/CR-10-초안.md` v0.1(2026-10-03). 형식은 `docs/CR-9-문구안.md`를 따르되, 새 내용이 많아 "넣을 위치 + 넣을 전문" 위주로 썼다.
- **승인 전에는 01·02·03·limits를 고치지 않는다.** 승인되면 아래 문구를 해당 위치에 붙여 넣고 `docs/.status`의 `doc_changes`에 기록한다.
- **항목별로 따로 넣을 수 있다.** 초안 6절의 사용자 결정(1번 "A~E 중 무엇을 넣을까")에 따라 일부 항목은 빠질 수 있다. 그래서 문구마다 앞에 꼬리표를 붙였다.
  - `[A]` 입력 기준 정형화 · `[B]` 찾기·거르기·주변만 보기 · `[C]` 표로 한꺼번에 입력 · `[D]` 문서 변환 다듬기 · `[E]` 실사용 전환 문서(선택) · `[공통]` 어떤 항목을 고르든 넣는 것
  - 고르지 않은 항목의 블록은 넣지 않는다. 표의 한 칸 안에 여러 항목이 섞여 있으면, 고르지 않은 항목의 꼬리표가 붙은 부분만 지운다.
  - **번호는 항목에 고정한다.** A를 빼도 R-17·R-18은 R-17·R-18이다(빈 번호 R-16을 남긴다). D-ID·T-ID·K-ID·L-ID도 같다. 번호를 당기면 초안·대화 기록과 어긋나기 때문이다.
- 표기: `〔…〕`는 **아직 채울 수 없는 자리**다. 사용자 결정·조력자 의견·실문서 시험 결과가 나오면 채운다(채울 때도 `doc_changes`에 기록).
- 용어 풀이(처음 나오는 곳에서 한 번만):
  - **표준 양식**: 업무를 유니버스에 넣을 때 "어디까지 노드로 쪼개고, 업무 노드에 어떤 속성을 채우는지"의 약속.
  - **거르기**: 조건(노드 유형·사람)에 맞지 않는 노드를 흐리게 해 맞는 것만 눈에 띄게 하는 것. 데이터는 바뀌지 않는다.
  - **주변만 보기**: 고른 노드와 바로 이어진 노드(1단계 이웃)만 남겨 다시 배치하는 보기.
  - **일괄 명령**: 노드 추가·수정 여러 개를 한 묶음으로 처리해, 전부 성공하면 한 번에 저장하고 하나라도 실패하면 아무것도 저장하지 않는 방식("전부 아니면 전무").
  - **기능 동결**: 정한 시점 뒤로는 새 기능을 만들지 않고 검증·영상·제출만 하는 것.
