## 1. 왜 필요한가 (현재 수준의 빈 곳)

| 영역 | 지금 | 실무에서 막히는 장면 |

## 2. 변경 항목

추천 순서는 B → C → A → D다. A·D는 조력자 의견과 실제 문서가 있어야 정할 수 있고, B·C는 지금 바로 만들 수 있으며 시연의 약점을 직접 고친다.

### A. 입력 기준 정형화 (새 R-16) — 조력자 의견 반영

| 항목 | 내용 |
|---|---|
| 요구 | 업무를 유니버스로 넣는 **표준 양식**을 정하고, 앱 안에서 그 기준을 보여 주고 점검한다 |
| 인수 기준 ① | 조건: 사용자가 업무 유니버스를 만들거나 가져온다 / 입력: 업무·사람·산출물·주제 노드 / 기대: 표준 양식(쪼개는 단위, 업무 노드의 필수 속성 — 예: 절차·주기·마감·주의사항 중 무엇이 필수인지)과 비교해 빠진 것을 "권장 항목 n개 비어 있음"으로 알린다 / 오류: 막지 않는다(알림만) |
| 인수 기준 ② | 내장 샘플이 모두 같은 양식을 따른다(카드승인 38개 사례는 "비교 자료"로 남길지, 양식대로 다시 만들지 결정 — D3-19 재검토) |
| 인수 기준 ③ | 실행 안내·가져오기 가이드에 "이렇게 넣는다" 1쪽이 있다 |
| 정할 것 | 쪼개는 단위(처리 단계를 노드로 / 업무 속성의 절차로), 필수 속성 목록 — **조력자 의견 뒤** |
| 기존과의 관계 | CR-5 ②("월말 정산 수준") 결정을 표준 양식으로 굳히는 것. 데이터 틀(12.2 스키마)은 바꾸지 않는다(속성 약속만, R-07) |

### B. 큰 화면 탐색: 찾기·거르기·주변만 보기 (새 R-17)

| 항목 | 내용 |
|---|---|
| 요구 | 노드가 많은 화면(팀·부서)에서 원하는 노드를 찾아 읽을 수 있게 한다 |
| 인수 기준 ① 찾기 | 조건: 노드 50개 이상 화면 / 입력: 이름 일부(예: "대사") / 기대: 맞는 노드 목록이 뜨고, 고르면 그 노드로 이동·확대된다 / 오류: 없으면 "찾는 노드 없음", 접힌 유니버스 안에 있으면 펼쳐서 보여 준다 |
| 인수 기준 ② 거르기 | 입력: 노드 유형(사람·업무·…)이나 사람 하나 / 기대: 해당하지 않는 노드를 흐리게 하거나 숨긴다. 거르기 상태가 화면에 표시되고 한 번에 풀 수 있다 |
| 인수 기준 ③ 주변만 보기 | 입력: 노드 하나 선택 + "주변만 보기" / 기대: 그 노드와 1단계(선택 시 2단계) 이웃만 남기고 다시 배치해 이름이 읽힌다 / 오류: 이웃이 없으면 그렇다고 알린다 |
| 인수 기준 ④ | 부서 화면(가상 운영부, 약 70노드)에서 위 셋으로 특정 노드의 이름을 읽을 수 있음을 스크린샷으로 확인 |
| 영향 | 02 5.3 화면 표에 조작 추가. 모듈: view(거르기·이웃 계산, 순수 함수) + ui. 규모 실측(L-25)도 함께 다시 잰다 |

### C. 표로 한꺼번에 입력·수정 (새 R-18)

| 항목 | 내용 |
|---|---|
| 요구 | 한 유니버스의 노드와 주요 속성을 표(행 = 노드)로 보고, 여러 행을 한꺼번에 넣거나 고친다 |
| 인수 기준 ① | 조건: 유니버스 열림 / 입력: 표에 행 여러 개 추가(유형·이름·설명·주요 속성) / 기대: 저장하면 그래프에 한 번에 나타나고 이력(created)이 남는다 / 오류: 행마다 기존 검증(E-REQUIRED·E-DUP 등)을 적용하고, 오류 행만 표시한 채 나머지는 저장하지 않는다(전부 아니면 전무) |
| 인수 기준 ② | 기존 노드의 이름·속성을 표에서 고치면 수정 이력(before/after)이 남는다(R-02 ③과 같음) |
| 인수 기준 ③ | 스프레드시트에서 복사한 표(탭 구분)를 붙여 넣을 수 있다(변환기 표 읽기 재사용) |
| 범위 밖 | 연결(관계)의 일괄 입력은 이번에 하지 않는다(양식이 복잡해짐 — 필요하면 다음 CR) |
| 영향 | 02 5.3 화면, 12.7 흐름 1(명령 여러 개를 하나로 저장 — 지금 노드 추가 뒤 꼭지 연결을 따로 저장하는 "저장 2회"(ui/main.js 노드 추가 양식, 성능 검토 지적)도 함께 해결). 모듈: model(일괄 명령), app, ui |

- **기능 동결:** 마감 전 일정 시점부터는 새 기능 없이 검증·영상(T-16)만 한다. 시점은 사용자가 정한다(계획 문서에 날짜를 적지 않는다).
- **항목마다 재검증:** 구현 → 검토 에이전트 → 수정 → "수정 전 판과 나란히" 재검증 에이전트까지 한 묶음으로 한다(2026-10-03 교훈).
- **우선 확인:** 이 CR을 승인해도 B부터 시작하기 전에 확인 목록(`.tmp/guide/확인-종합.md`)의 앞 항목들을 먼저 끝낸다.
