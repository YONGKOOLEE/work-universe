## 2. A. 편집 되감기 (새 R-25, D-30)

| 항목 | 내용 |
|---|---|
| 요구 | 유니버스가 언제 어떻게 고쳐졌는지 시점을 골라 그때의 지도를 보고, 필요하면 그 시점으로 되돌린다 |
| 원리(D-30) | 저장 방식을 바꾸지 않는다. 생성·수정(수정 전·후 값)·숨김·되살림·연결·묶기·통합 판정이 이미 이력에 있으므로, **지금 문서에서 그 시점 뒤의 이력을 거꾸로 적용**해 과거 문서를 만든다(순수 함수, `model/rewind.js`). 추가 저장 없음 |
| 인수 기준 ① | 유니버스 개요(아무것도 고르지 않은 화면)의 「편집 되감기」 → 고친 시점 목록(같은 기록 시각을 한 판으로, "날짜 시:분 · 바뀐 n건")과 막대. 고르면 그 시점 지도가 **읽기 전용**으로 그려지고, 머리에 "편집 되감기 중 — 시점(읽기 전용)" 띠와 「지금으로 돌아가기」 |
| 인수 기준 ② | 그 시점 뒤에 **생긴 것·바뀐 것·숨긴 것** 수를 보여 주고, 노드를 누르면 그때 값이 상세에 나온다(바뀐 칸 표시) |
| 인수 기준 ③ | 「이 시점으로 되돌리기」 → 확인 창 → 지금 문서를 그 시점과 같게 만드는 명령을 **한 묶음(전부 아니면 전무)**으로 적용: 그 뒤 생긴 노드·연결은 숨김, 그 뒤 숨긴 노드는 되살림, 바뀐 칸은 그때 값으로 수정, 그 뒤 숨긴 연결은 같은 내용으로 새로 만듦. 각 이력에 메모 "편집 되감기: (시점)으로 되돌림". 되돌림도 되감기 목록에 한 판으로 남아 다시 되돌릴 수 있다 |
| 인수 기준 ④ | 되감기 결과는 옛 판을 그대로 만든다: 무작위 편집 순서를 만들고 시점마다 찍어 둔 문서와 되감기 결과가 같다(속성 시험, 5절) |
| 오류 | 이력이 한 시점뿐 → "고친 기록이 아직 없습니다". 되돌릴 것이 없음 → 버튼 막음. 읽기 전용(내용 포함 HTML)·형식 버전 다름 → 보기만, 되돌리기 막음. 저장 실패 → W-STORAGE, 문서 그대로 |
| 한계(알림) | 「바로 삭제」(연결·이력 없는 실수 노드)와 하위 유형 추가는 이력을 남기지 않아 되감기에 보이지 않는다. 「완전히 삭제」한 노드는 일부러 내용을 지웠으므로 자리표시로만 나온다. 문서 변환·JSON 가져오기·샘플처럼 한꺼번에 들어온 노드는 들어온 시점이 첫 판이다. 묶은 지도(상위 유니버스)는 되감지 않고, 하위 유니버스를 열어 되감는다 |
| 헷갈림 막기 | 기존 「시간 보기」는 "업무가 언제 누구 것이었나"(업무 시간), 「편집 되감기」는 "지도가 언제 어떻게 고쳐졌나"(기록 시각). 이름·위치·띠 문구로 나눈다 |

## 3. B. 인수인계 위험 인사이트 (새 R-26, D-31)

모두 LLM 없이 규칙으로 계산하고(5.5 원칙), 근거 노드·수치를 붙인다. 데이터가 모자라면 결론 없이 부족 사실만 보인다. 상수는 `rules/insight-risk.js` 한 곳.

| 인사이트 | 규칙(답이 없으면 값) | 근거 | 데이터 부족 |
|---|---|---|---|
| **① 지식 집중 위험** | 활성 업무 중 **해 본 사람**(과거·현재 수행 연결의 서로 다른 사람, 역할 노드 제외)이 1명이고, 그 업무의 인수인계 이력·인수인계서가 없으면 "높음". 1명이지만 인수인계 기록이 있으면 "주의" | 업무, 그 사람, "인수인계 0건" | 수행 연결이 없는 업무(밀집·공백에서 따로 보임), 역할 노드만 있는 업무는 "사람 미확인" |
| **② 인수인계 준비도** | 업무마다 6항목 충족 수(점수 대신 **n/6과 빠진 항목**): 표준 양식 권장 항목 채움 · 미해결 이슈 0건 · 산출물 연결 1개 이상 · 현재 담당자 있음 · 인수인계 이력 또는 인수인계서 있음 · 최근 이력 180일 이내(기준일 = 시간 보기의 날짜). 낮은 순으로 나열 | 빠진 항목마다 해당 노드·메모 | 업무가 없는 유니버스 |
| **③ 파급 영향** | 업무에서 **선후행**(앞 → 뒤)과 **산출 → 참조**(이 업무의 산출물을 다른 업무가 참조)를 따라 닿는 업무 수. 많은 순 상위 5개("길목 업무")와, 현재 혼자 맡은 사람이 빠질 때 함께 막히는 업무 수 상위 5명 | 닿는 경로 한 줄(업무 → 업무 → …) | 선후행·참조 연결이 없는 유니버스 |

- **화면(답이 없으면 값):** 인사이트에 탭 하나 **「인수인계 위험」**(안에 ①②③ 세 절)을 더한다. 탭을 셋 늘리지 않는 이유: "방대하다"는 첫인상(CR-13 A). 업무 상세에는 ①이 "높음"이면 한 줄 표시(반복 비효율 표시와 같은 자리).
- **설명 문장:** 샘플 데이터의 ①②③ 요약 문장은 **사전 생성(개발 중 Claude가 근거만 보고 작성)**으로 넣고, 열 때 근거 ID를 검증해 맞지 않으면 규칙 기반 문장으로 바꾼다(R-15·D-12와 같은 방식). 새로 입력한 데이터는 규칙 기반 문장.
- **묶은 지도:** 통합(같은 사람·같은 업무) 결과를 반영한 화면 기준으로 계산한다(기존 인사이트와 같음).

## 4. C. 폴더 연결 (새 R-27, D-32) — 조건부, A·B 뒤

| 항목 | 내용 |
|---|---|
| 먼저 시험(차단) | Chrome·Edge의 폴더 접근 기능(File System Access API)이 ① `file://`로 연 index.html ② https 주소에서 되는지, ③ 동기화 폴더·네트워크 드라이브를 고를 수 있는지, ④ 한 번 허락한 폴더를 다음에 기억하는지. 결과를 tech-record에 남기고, 안 되면 C는 하지 않고 발표 "다음 단계"로 돌린다 |
| 방식(D-32, 답이 없으면 값) | **브라우저 저장소가 원본, 폴더는 거울.** 「폴더 연결」을 하면 저장할 때마다 내 유니버스를 그 폴더에 `작성자이름.json`(이름이 없으면 유니버스 ID)으로 내보내고, 폴더의 다른 사람 파일 목록을 읽기 전용으로 보여 준다. 「팀 지도로 묶기」 → 기존 가져오기·묶기·통합 확인으로 이어진다. 폴더를 원본으로 바꾸는 일(용량 한도 해소)은 다음 단계 |
| 인수 기준 | ① 폴더를 고르면 내 파일이 생긴다 ② 동료 파일 3개(가상)가 목록에 보이고 「팀 지도로 묶기」로 묶인다 ③ 「새로 고침」으로 바뀐 파일을 다시 읽는다 ④ 남의 파일은 고치지 않는다 |
| 오류 | 기능 없음(Firefox 등)·허락 거부 → 단추를 숨기거나 이유 표시, 지금처럼 내보내기·가져오기 안내. 파일이 깨짐·형식 다름 → 그 파일만 건너뛰고 알림 |

## 5. 검증 (완료 기준)

- **A:** 무작위 편집 순서(노드·연결 추가·수정·숨김·되살림·삭제·통합 판정) 200회 이상을 만들고, 시점마다 찍은 문서와 `rewind(doc, 시점)`이 같은지 비교하는 속성 시험. 되돌리기 뒤 문서가 그 시점과 같은지(숨김 처리 차이만 허용) 비교. 결함 주입(되돌리는 순서·수정 전 값·숨김 되돌리기를 틀리게) 확인.
- **B:** 규칙마다 읽혀야 하는 것·읽히면 안 되는 것을 함께 시험(예: 해 본 사람 2명, 역할 노드만, 인수인계서만 있음, 참조 순환). 내장 샘플 7개 결과를 고정 비교로 두고 사람이 판정.
- **C:** 시험 결과 기록, 가상 파일 3개로 묶기 흐름. 실제 공유 드라이브는 사람 확인(미확인으로 남김).
- **공통:** 나란히 재검증(Opus 하위 에이전트, 경계 사례 직접 생성), `npm test`, `check:chrome`(새 화면 스크린샷 확인), 끝에 `check:submit`(Chrome·Edge).

## 7. 순서와 범위 줄이기

- **구현 순서:** A(되감기 보기 → 되돌리기)와 B(①→②→③)를 Sonnet 하위 에이전트 둘이 파일 영역을 나눠 나란히(A: `model/rewind.js`·`ui/rewind.js`, B: `rules/insight-risk.js`·`ui/insight.js`). 메인(Opus)이 확인·나란히 재검증·커밋. 그 뒤 C 시험 → 되면 C.
- **시간이 모자라면 빼는 순서:** C → B③ → A의 되돌리기(보기만 남김) → B②. ①과 되감기 보기는 남긴다.
- **동결:** 사용자 결정으로 나중에(F23-7 보류). 영상·소개자료·대리 관찰에 필요한 날을 고려해 다시 묻는다.
