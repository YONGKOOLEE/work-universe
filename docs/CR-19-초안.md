# CR-19 — 글로 추가 (줄글에서 항목·연결 만들기)

- 문서: CR-19 v0.2 · 상태: **approved(2026-10-25, 사용자 명시 승인 "지금 그대로 승인 (추천)" — 질문 "CR-19 「글로 추가」를 지금 구현된 그대로 승인하나요?"의 선택지 답, docs/.status approvals)** — 승인 범위는 구현된 그대로(C19-9 처음에는 아무것도 체크하지 않음, C19-10 지도에 있는 항목은 체크 칸 없이 이어 씀)이고, 01 R-29·02 D-37·03 T-42의 기존 반영을 이 승인으로 확정했다.
- 요청(2026-10-24, docs/.status doc_changes 원문 그대로): "표로입력이나 가져오기 같이 큰 볼륨말고도 줄글 형식으로 역할이나 내용을 넣어주면 노드랑 관계를 만들어주는 기능도 추가했으면 좋갰는데 llm활용하거나 이건 규칙기반도 나쁘지ㅜ않을거같고 사용자가 확인해서 수정히면 되니까". 이 요청 뒤 구현·승인 문서 반영(10-24~25)이 명시 승인보다 먼저 이루어졌다(열 번째 검토 RV10-2·3 — v0.1은 요청을 승인으로 보았고 인용도 고쳐 적었음, CR-20에서 바로잡음). 아래 "답이 없으면" 값은 메인이 정했고 decisions-pending 21·23절에 쌓았다.
- 근거: 일상 사용 점검(CR-18-8)에서 팀원 기록은 메모류가 쉽고 사람·연결 넣기는 조작이 많았다(협업자 추가 11번). 「표로 추가」·「가져오기」는 큰 볼륨용이라, 회의 메모·인수인계 메모처럼 몇 문장짜리 글을 바로 지도에 반영할 길이 없다.

## 무엇을

「사람·업무·문서 추가」 옆에 **「글로 추가」**. 몇 문장(예: "서하늘(V-1003)이 대사 확인을 맡는다. 대사 확인이 끝나면 보고를 한다. 보고에서 월말 정산 보고서를 만든다. 감사팀 도하람에게 결과를 공유한다.")을 붙여 넣고 「읽기」를 누르면:

1. **미리 보기 — 항목:** 글에서 찾은 사람·업무·산출물·조직·주제. 행마다 [넣기 □](새 항목만 — 처음에는 비어 있음. 지도에 이미 있는 항목은 체크 칸 없이 늘 이어 씀, C19-9·C19-10. v0.1의 "[넣기 ✓]"를 CR-20에서 고침) 유형(고르기) 이름(고칠 수 있음) 상태(「새로 만듦」 / 「있는 항목 「…」에 연결」 — 같은 이름·사번이면 있는 것을 쓰고 새로 만들지 않음) 원문 구절.
2. **미리 보기 — 연결:** [넣기 □](처음에는 비어 있음 — 연결을 체크하면 새 끝 항목도 함께 체크, C19-10) 앞 항목 — 관계(고르기, 두 유형에 쓸 수 있는 것만 — CR-18-4와 같은 규칙) — 뒤 항목, 원문 구절. 이미 같은 연결이 있으면 「이미 있음」으로 빼 둠.
3. **처음에는 아무것도 체크되어 있지 않다(재검증 R16~R18 뒤 결정, C19-9)** — 하나씩 체크하거나 「지도에 있는 항목끼리 연결 체크」·「모두 체크」. **「저장」:** 체크한 것만 한 번의 기록(applyBatch, 되감기 한 점). 하나라도 오류면 아무것도 저장하지 않고 그 행을 표시(표로 추가와 같은 전부 아니면 전무).
4. 읽지 못한 문장은 「읽지 못한 문장」 목록으로 보이고, 지어내지 않는다.

### 읽는 방식 두 가지
- **규칙 기반(기본, 키 없이):** 문장을 나눠 정해진 모양만 읽는다 — "X(이/가/은/는) Y(을/를) 맡는다·담당·처리" → 수행, "Y 담당(은/는/:) X" → 수행, "Y(에서/로) Z(을/를) 만든다·작성·산출" → 산출, "Y(이/가) 끝나면·다음에·뒤에 Z" → 선후행, "X(은/는) T 소속·T의 X" → 소속, "X에게 공유·문의·협업" → 참조, "(V-1234)" → 사번, 이름 끝말(보고서·자료·문서·양식·파일·대장·표·서·계획서·결과) → 산출물. **(재검증 R16 뒤) 부정·과거·예정·조건·질문·전언, 날짜·기간, 나열, 대명사·직함 단독이 있는 문장은 읽지 않는다 — 애매하면 「읽지 못한 문장」(놓치는 것은 괜찮고 잘못 읽는 것은 안 됨).** 사람인지 모를 이름은 「확인 필요」 표시로 사람 후보.
- **Claude(키가 있을 때 「Claude로 읽기」):** 같은 미리 보기 모양(항목·연결·원문 구절)을 구조화 출력으로 받고, **원문 구절이 글에 그대로 있는지(quote 검증)**·유형·관계가 스키마 규칙에 맞는지 검사해 통과한 것만 보인다(D-33과 같은 원칙). 실패·키 없음이면 규칙 기반으로. 보내는 것은 붙여 넣은 글과 지금 지도의 항목 이름·유형 목록(최대 200개 — C19-5, CR-20에서 "이름 목록"을 고침)뿐(연결할 대상을 찾기 위해) — 「키와 데이터」 도움말에 한 줄 더함.

### 하지 않는 것
- 묶은 지도(팀·부서)에서는 단추 대신 "팀·업무 지도를 열어 넣으세요" — 하위 지도 항목과 겹쳐 같은 사람이 둘 생기는 것을 막는다(재검증 R16-11).
- 날짜가 있는 담당 기간·이력(메모) 만들기 — 1차 후(지금은 「이번 주 기록」·이력 추가로).
- 기존 항목의 이름·속성 고치기, 삭제.
- 사전 생성(사용자가 쓰는 글이라 미리 만들어 둘 수 없음).

## 반영할 곳
01 새 R-29(인수 기준), 02 D-37·5.3 화면 행·12.7 모듈, 03 T-42, limits(규칙 기반의 읽는 범위), decisions-pending 21절, 실행안내 한 줄·도움말 「키와 데이터」 한 줄.
