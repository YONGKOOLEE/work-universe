## 1. 결론

**화면 탭 하나로 넣는 것은 맞지만, 유니버스처럼 "같은 데이터를 다르게 보는" 통합은 아니다. 파이썬 앱을 그대로 붙일 수 없어 TypeScript로 옮겨 `itda/src/assistant/`에 새로 넣는다. 고객 데이터는 사용자 결정(7절)에 따라 업무 데이터(AppState)에 함께 둔다.**

| | 업무 유니버스 합칠 때 | ClientMemory 합칠 때 |
|---|---|---|
| 데이터 | AppState에서 파생(새 저장 거의 없음) | 고객·활동·요청·기념일 **새 데이터** |
| 코드 | JS 순수 모듈을 그대로 불러 씀 | Python·SQLite·서버 → **옮겨 써야 함** |
| 공유 | 팀 데이터 | 개인 영업 메모(**개인정보**) |

## 3. 합치는 방식 비교

| 방식 | 판단 | 이유 |
|---|---|---|
| A. iframe·링크로 파이썬 앱 연결 | ✗ | 업무잇다는 `index.html` 더블클릭으로 돌아야 함(기술 제약). 파이썬 설치·서버 실행이 필요하고, ClientMemory가 `X-Frame-Options: DENY`로 끼워 넣기를 막음. 심사 환경에서 안 돌 위험 |
| **B. TS로 옮겨 내부 모듈로(추천)** | ○ | 한 파일로 동작. 키·AI 엔진·디자인·밝기·권한 안내를 공유 |
| C. 별도 프로그램으로 함께 제출 | △ | 비용은 가장 낮지만 「하나의 프로그램」 결정(U-1, U-2)과 어긋남 |

## 4. 설계 (방식 B)

### 4.1 구조

```
itda/src/assistant/
  types.ts        고객·활동·요청·기념일·변경 이력·질문 상태
  store.tsx       별도 저장(4.2), 저장 실패·다른 탭 알림은 store.tsx와 같은 방식
  model.ts        등록·수정·삭제·이력·복원·중복 확인·최근 연락일   ← db.py, server.py
  today.ts        오늘 할 일·다음 할 일 규칙                    ← api_dashboard
  notices.ts      기한·생일·미팅 알림(저장 없이 계산)             ← notify.py
  briefing.ts     미팅 브리핑                                  ← briefing.py
  followup.ts     미팅 후 질문·반영안                          ← followup.py
  nlsearch.ts     규칙 해석·검색·근거                          ← nlsearch.py
  claude.ts       가림 처리·대화 분석·질문 해석(llm.ts 사용)      ← ai.py
  seed.ts         가상 고객 18명
  AssistantPage.tsx 외 화면  React + 기존 ui.tsx·디자인 토큰
```

- `.ts` 순수 모듈은 DOM·저장소를 쓰지 않고 Node 단위 시험으로 검증한다(기존 규칙과 같음).
- 화면(JS 1,532줄)은 문자열 HTML이라 재사용하지 않고 React로 새로 만든다. **작업량 대부분이 여기다.**
- 건드리는 기존 파일은 `App.tsx`(경로), `Layout.tsx`(메뉴 1개·알림 수), `llm.ts`(호출 한도 항목)로 줄인다.

### 4.2 데이터 — 업무 데이터에 포함 (사용자 결정)

- **저장 위치:** `AppState.assistant`(선택 칸). 기존 저장 데이터를 열면 비어 있을 때만 가상 고객 18명을 채운다.
- **열람·편집(기본값, 한 함수로 둠):** 모두 볼 수 있고, 고치는 것은 고객의 담당 영업자(`ownerId`)와 그 사람 조직 범위의 조직장. 팀 업무 규칙과 같은 방식이다.
- **백업·합쳐 불러오기:** 백업 파일에 고객 데이터가 함께 들어간다. 합쳐 불러오기는 이름+소속·휴대전화·이메일로 같은 고객을 찾아 현재 값을 유지하고, 없는 고객만 더한다.
- **기존 AI 호출:** 고객 데이터는 업무 검색·점검·인사이트로 보내지 않는다(시험으로 고정). 지도·스냅샷에도 넣지 않는다.
- **사진·명함 이미지:** 저장하지 않는다(5MB 저장소 보호). 머리글자 표시로 대신한다.
- **대화 원문·분석 초안:** 메모리에만 둔다(새로 고침하면 사라짐). 사용자가 「원문 보관」을 고른 경우만 저장.

**결정으로 받아들인 위험(사용자 선택, 화면 경고 없음):** 백업 파일을 팀에 넘기면 전화번호·생일 등도 함께 넘어간다. 저장 내용은 암호화되지 않고, 사용자 전환은 인증이 아니며, `file://`로 연 다른 HTML과 저장소가 공유될 수 있다(`docs/limits.md` L-24). 시연 데이터는 가상만 쓴다. 전송 전 내용 확인은 AI 분석 흐름의 일부로 유지한다.

| 안쪽 탭 | 내용 | 원래 메뉴 |
|---|---|---|

| 고객 | 목록·거르기, 상세(개요·선호·히스토리·요청·경조사·변경 이력), 브리핑 단추 | 고객관리, 미팅 브리핑 |

### 4.4 그대로 못 옮기는 것

| 기능 | 합친 뒤 | 이유 |
|---|---|---|
| Windows 알림, 자동 실행, 창 닫혀도 알림 | **없음.** 탭을 연 동안만 메뉴 숫자와 오늘 화면에 표시 | 서버 없는 HTML 파일은 백그라운드 실행 불가 |

### 4.5 범위

| 묶음 | 내용 | 시점 |
|---|---|---|
| **A(추천 1차)** | 고객·이력·복원, 활동·요청·경조사, 오늘, 브리핑, 미팅 후 질문, 규칙 검색, 대화 분석(Claude + 승인), 가상 데이터 | 탭 1차 |
| B | 명함 인식(`llm.ts`가 이미지를 받게 확장), 비서 데이터 백업·전체 삭제 UI 보강, Claude 질문 해석 | A 뒤 |
| C | **업무와 연결**: 고객 ↔ 업무·협의처 연결, 고객 요청 → 조치 제안(승인 후 반영), 미팅 → 타임라인 제안, **인계 때 고객 관계 넘기기(사적 항목 제외, 항목별 선택)** | 후속 |

C가 제품 목적인 「담당자가 바뀌어도 맥락이 끊기지 않는다」와 이어지는 부분이다. 탭만 넣으면 CRM이 옆에 붙은 것처럼 보일 수 있어, 소개자료에는 이 방향을 한 줄로 밝히는 것을 권한다.
