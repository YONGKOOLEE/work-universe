- 관련: R-09, T-22(CR-10 E), 02-design 6절·1.6·5.2·5.4, limits L-4·L-9·L-21·L-22·L-24·L-25

## 0. 읽는 법

사내 정책·시스템·규정에 관한 문장에는 두 표시 중 하나가 붙는다.

- **확인됨(출처: 파일·절)** — 저장소 문서에 근거가 있다.
- **미확인 — 확인 주체: ○○** — 근거가 없다. 사실로 쓰지 않았고, 누가 확인해야 하는지만 적었다.

사내 시스템 이름은 모르므로 "사내 인사 시스템(이름 미확인)"처럼 쓴다. 기간·인원·비용 숫자는 근거가 없어 쓰지 않았다.

## 3. R-09 네 주제

### 3.1 실데이터 연결

| 항목 | 내용 |
|---|---|
| 원칙 | 연결 전에 어떤 데이터가 **들어와도 되는지**부터 정한다. 실사용 시 인사·조직 데이터(사번·소속·담당 이력)는 민감정보다(확인됨: 00-context 3절). 정보 분류·반출 규정의 구체 내용은 미확인 — 확인 주체: 사내 정보보호 담당. |
| 입력 경로(현재) | 폼 입력, 표 붙여넣기(R-18), 새 업무 지도의 첫 업무 칸, JSON 가져오기, 문서 붙여넣기 초벌 변환, 가져오기 미리 보기에서 사람이 확인 후 확정(확인됨: 01 R-02·CR-5). |
| 사내 시스템 연동 | 연동 대상(인사 시스템, 협업툴 문서 저장소 등)과 접근 방식은 미확인 — 확인 주체: 사내 시스템 담당자. 협업툴·사내 게시물에 업무 지식이 흩어져 있다는 것은 사용자 진술이다(확인됨: 00-context 1절 B1, 정량 증거는 미확인). |
| 사번 기반 대응 | 업무 유니버스의 사람과 조직관리 업무 지도의 사람을 사번으로만 대응시키는 설계가 있다(확인됨: 02 1.6). 실제 사번 체계(형식·재사용·재입사 시 부여)는 미확인 — 확인 주체: 인사·조직관리 담당. 재입사 시 사번 두 개는 현재 지원 밖이다(L-1). |
| 이미 준비된 것 | 사번 대응·충돌 확인 목록(R-11, merge 모듈), 가져오기 검증(model/import.js), 가상 데이터 점검 도구 |
| 아직 없는 것 | 실제 시스템 읽기 연동, 정기 동기화, 실데이터 반입 승인 절차 |

| 아직 없는 것 | 전송·저장 암호화, 접근·변경 로그의 서버 보존, 보관·파기 정책, 보안 검토 통과 기록 |

### 3.4 조직관리 업무 지도의 기준 데이터 검증 역할

- **현재:** 조직관리 업무 지도(U-O)는 같은 틀의 일반 업무 지도 하나로만 시연한다. 다른 업무 지도의 소속을 검증하거나 덮어쓰지 않는다(확인됨: 02 1.6, limits L-4, 정의서 v0.2 §12-2).
- **구상(미결정):** 사람·조직은 조직관리 업무의 데이터이므로(확인됨: 00-context 1절 "유니버스 개념" 2), 실사용에서 조직관리 업무 지도가 사번·소속의 **기준**이 되고 업무 유니버스가 이를 참조·검증하는 구조를 검토할 수 있다. 채택 여부와 책임 범위는 결정 필요(7절 Q4).
- **짚어 둘 점:** 실제 어느 부서·직무가 조직·인사 기준 데이터를 관리하는지는 미확인 — 확인 주체: 사용자(조직 관리 역할 대상 직무도 미확인, 확인됨: 00-context 2절). 기존 인사 시스템이 이미 기준 역할을 하는지도 미확인 — 확인 주체: 인사·조직관리 담당. 둘이 겹치면 이중 관리가 된다.
- **이미 준비된 것:** 사번 대응, 소속 변경 이력(조직개편 후에도 업무 이력 유지, R-14), 사번 충돌·사번 없음 확인 목록.
- **아직 없는 것:** 기준 데이터와의 불일치 검출·알림, 조직 ID 기준 소속 검증(조직 ID가 없으면 "미기재", L-8).

## 4. 운영 모델

누가·언제·왜 계속 입력하는지를 코드·문서에서 확인되는 만큼만 적는다.

| 질문 | 현재 확인되는 것 | 결정 필요 |
|---|---|---|
| 언제 입력이 쌓이나 | 담당자 교체 때 앱이 이력으로 초안을 만들고, 사람이 내용을 확인해 「확정해 인수인계서로 저장」하면 인수인계서(확정자·시각·본문)와 인수인계 이력이 남아 다음 초안의 근거가 된다(확인됨: 01 R-03 ③, CR-8). 즉 인수인계 한 번이 다음 사람의 시작 자료가 된다. | 평소 업무 중 메모·산출물 입력을 누가 어느 주기로 하는가. 사내에 정해진 입력 규칙이 있는지는 미확인 — 확인 주체: 사용자. |
| 누가 입력하나 | 일반 구성원이 업무 지도 생성·자료 업데이트·탐색·초안 생성, 인수인계 담당자·인수자가 검토·확정(확인됨: 00-context 2절. 인수인계 역할은 [제안]). | 인수인계 확정을 정식 절차로 삼을지 — 확인 주체: 조직 책임자(미확인). |
| 조직·사람 이력은 누가 | 조직관리팀 업무로서 조직관리 업무 지도에 계속 입력하는 구조가 개념에 있다(확인됨: 00-context 1절 "유니버스 개념" 2). 실제 담당 부서·사람은 미확인 — 확인 주체: 사용자. | 책임자 지정, 입력 주기, 대리 담당 |
| 입력이 끊기면 | 마지막 입력 이후 기간을 0건으로 세지 않고 "입력 없음 — 데이터 부족"으로 보인다(limits L-9, R-05 ②). 이력이 없는 초안 항목은 "이력 부족"으로 표시하고 지어내지 않는다(R-03 ②). 입력 누락은 숨겨지지 않고 화면에 드러난다. | 끊김을 누가 보고 누구에게 알리는가(알림·점검 주체) |
| 입력 부담 | 표준 양식(R-16), 표 붙여넣기(R-18), 첫 업무 칸, 문서 초벌 변환(CR-5)으로 줄이려는 설계가 있다. 실제 부담은 측정하지 않았다(확인됨: 00-context 1절 B2·B3 정량 증거 미확인). | 실무 도입 전 시범 팀에서 측정 |

## 6. 단계별 로드맵 (순서와 선행 조건만)

1. **합의 단계:** 7절 결정(Q1~Q8)을 받는다. 선행: 이 문서 승인. 코드 변경 없음.

3. **공유 기반 단계(X2→X3):** 서버 저장과 로그인. 선행: 호스팅 환경·인증 방식 확인.
4. **권한·함께 쓰기 단계(X4→X5):** 선행: 3단계와 권한 모델 결정.
5. **연동 단계(X6·X7):** 선행: 연동 대상 확인과 기준 데이터 역할 구분.
