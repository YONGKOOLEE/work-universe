## 1. 한눈에

- 기능은 1차 제출에 충분하다. **남은 4주의 병목은 코드가 아니라 사람 몫(영상·소개자료·조력자 회신·다른 PC 확인)과 샘플 이야기·AI 활용 설명**이다(검토 ④).
- 저장 데이터에 남는 결함 2건(높음): 연도 오타 날짜 하나로 유니버스가 열리지 않음(C-1), 부서·팀 화면에서 확정한 인수인계에 다른 유니버스의 사람 ID가 저장됨(C-2).
- 시연에서 바로 보이는 작은 결함: 업무 양식에 사번 칸(U-1), 빈 메모 저장(U-2), 확정 직후 결과가 안 보임(U-3), 가져오기 미리 보기의 빨간 오류(U-6).

## 5. 목적 적합성·일정 (검토 ④)

강점: 초안이 실제 문서로 쓸 만함(근거 칩), 원래 문제와 샘플 이야기가 맞물림(구두 인계 → 반복 비효율 → 확정), 지어내지 않음이 일관됨, 실행 장벽 없음, 같은 틀로 업무 → 팀 → 부서와 예외.

약점:
1. 실시간 LLM이 없음 — 「생성 방식」에 "P2, 1차 제출 범위 밖"이 그대로 보이고, 새 자료는 모두 규칙 기반. "AI 활용" 배점에 대한 답이 약함.
2. 인사이트 절반이 "그래서 뭐?" — 공백 9건 중 7건이 "담당 기록 없음"(입력 누락처럼 보임), 유사 경험자가 "운영 담당(V-4002)" 같은 이름 없는 역할, 흐름 변화의 최다 기간이 문서 가져온 날, 주제 반복이 「대사 불일치」 하나에 기댐.
3. 큰 화면의 시각 설득력(T-18로 보완했지만 기능을 알아야 씀).
4. 확산 가능성에 답할 자료 없음(저장은 브라우저 한 곳, 운영 모델, T-22 미작성).
5. 제출물 3종 중 영상·소개자료 미착수, 효과 수치 없음.

심사 예상 질문 10개 중 준비 약함·없음 7개: 입력 부담, 기존 도구와의 차이, AI를 어디에 쓰나, 보안·권한, 여러 사람·저장, 운영 주체, 효과.

우선순위 제안: 조력자 글 발송·메일 첨부 시험(사용자, 즉시) → 시연 대본 초안 + 샘플 이야기 보강 → T-22 → T-19 → (답이 오면) T-20 최소판 → 동결 → T-14 반영 → T-16 촬영 → T-15. T-21은 빼기를 권함. 범위 축소 순서에서 T-22는 T-19보다 나중에 빼는 쪽(03 3절 변경, CR).

계획에 없는 개선 제안(효과/크기/CR):
- P-1 3분 시연 이야기 흐름(대본 초안)을 지금 씀 — 높음/작음/불필요
- P-2 샘플 보강: 월말 정산의 자료 수집·보고에 담당·이력, 공백은 의도한 1~2건만, 카드승인 역할에 가상 이름 — 높음/중간(사전 생성·정답 표 연쇄)/카드승인은 D3-19와 겹쳐 사용자 확인
- P-3 AI 활용 설명 한 장(규칙이 근거를 찾고 LLM은 문장만, 근거 ID 검증, 개발·검증 과정) — 높음/작음/불필요
- P-4 영상용 실시간 LLM 경로 — 높음/중간~큼/필요(R-15 P2 → P1)
- P-5 소개자료에 기존 도구 비교표와 운영 모델 한 줄 — 높음/작음/불필요
- P-6 인사이트에서 다음 행동으로(반복 비효율 카드에 "초안 만들기") — 중간/작음/필요할 수 있음
- P-7 확정한 인수인계서 인쇄·파일 저장 — 중간/작음~중간/필요
- P-8 흐름 변화를 작은 막대와 한 줄 해석으로 — 중간/작음~중간/필요할 수 있음
- P-9 조력자에게 한 줄 설문(최근 인수인계 시간, 구두/문서) — 중간/작음/불필요
- P-10 「생성 방식」 창의 내부 용어를 심사자용 문구로(U-13과 같음) — 낮음~중간/작음/불필요

하지 않기를 권하는 것: T-21과 D-P 정책 구현, 카드승인 샘플을 표준 양식으로 다시 만들기, T-18 추가 미세 조정, 수천 노드 대비, 제출물에 실시간 LLM, 문구 CR·재검증을 더 늘리는 일.

일정 위험: 구현 속도는 충분. 병목은 사람 몫(조력자 글 미발송, 동결 날짜 미정, 영상이 가장 늦게·짧게 배치, 메일 차단·다른 PC 미시험), 늦은 기능의 회귀(T-19는 저장 경로를 건드림), 사용자 확인이 밀림.
