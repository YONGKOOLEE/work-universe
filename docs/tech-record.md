## 3. 빌드 방식 (P-1)

- 소스: `app/src`의 ES 모듈(`import`/`export`). Node 단위 테스트가 그대로 불러온다.
- 빌드: `npm run build` → esbuild `format: iife` → `dist/app.js`(모듈 없는 단일 스크립트, 약 442KB, 최소화) + `dist/index.html`(일반 `<script src="app.js">`).
- 빌드 스크립트가 결과물에 `type="module"`, `import`/`export` 문, `fetch(` 호출이 없는지 검사하고, 있으면 실패한다.
- 샘플 데이터는 JS 모듈로 감싸 번들에 포함한다(12.1).
- 대안 K-3(인라인 단일 HTML)은 쓰지 않았다. 스크립트 파일 분리 방식으로 P-1이 통과했기 때문이다.

## 6. T-03 구현 해석 (2026-09-30)

02-design 12절이 정하지 않은 부분을 아래처럼 해석했다. 12절과 충돌하지는 않는다. 다르게 하려면 알려 달라.

| # | 상황 | 구현한 해석 | 이유 |
|---|---|---|---|
| 1 | 숨긴 노드·연결과 같은 것을 다시 추가 | 중복 판정에서 **숨긴 것은 제외**한다 | 사용자에게 숨김은 삭제다. 막으면 "삭제했는데 다시 못 만드는" 상태가 됨. 1.5는 이 경우를 정하지 않음 |
| 2 | 꼭지 숨김·꼭지 이름 변경·꼭지 추가 | 거부하고 `E-SCHEMA`(field 표시) | 1.2 "숨길 수 없음", 꼭지 이름 = 유니버스 이름. 12.5에 맞는 전용 코드가 없어 `E-SCHEMA`를 씀 |
| 3 | `handover.payload.previous_handover_id` | **같은 문서의 인수인계 이벤트 ID**로 해석 | 12.2는 형식만 있고 대상이 명시되지 않음. 반복 비효율 규칙 ①(D-08)에서 이 값을 이벤트로 따라감. T-11에서 다르게 필요하면 함께 고침 |
| 4 | 부모가 꼭지를 참조할 때 그래프 | view가 부모 꼭지 → 자식 꼭지 **합성 연결**(포함, `synthetic: true`)을 만든다 | 참조만으로는 그래프가 끊겨 보임. 원본 문서에는 넣지 않음 |
| 5 | 동일성 연결로 합칠 때 대표 노드 | 먼저 나온 노드(기준 유니버스 우선)가 대표. 합쳐진 노드 사이의 연결은 자기 연결이라 그리지 않음 | 12절에 대표 규칙이 없음 |
| 6 | `decided_by`·`decided_at` 필수 | `method: human`이면서 `status`가 `confirmed`·`rejected`일 때만 필수 | "human일 때 필수"를 그대로 쓰면 확인 대기(pending) 연결을 만들 수 없음 |
| 7 | 스키마 버전이 다른 문서 | `E-SCHEMA` + `readOnly: true`를 돌려준다. 읽기 전용으로 여는 것은 화면(app) 몫 | 12.1 "경고하고 읽기 전용으로 연다" |
| 8 | 하위 유형 등록·유니버스 이름 중복 경고 | 하위 유형 등록은 이벤트를 남기지 않는 설정 변경. 같은 이름+단위 유니버스 경고는 저장소를 아는 app에서 T-09에 구현 | 이벤트 payload에 유니버스 대상이 없고, model은 다른 유니버스를 모름 |
| 9 | 수행 연결을 만들 때 `assign_start` 이벤트 | 자동으로 만들지 않는다. `created`만 기록하고, 담당 이벤트는 `addEvent`로 입력 | 1.4는 자동 기록 대상을 생성·수정·숨김으로 한정 |

### 7.1 설계 4절 사례 1에 더한 것 (확인 요청)

설계 4절 사례 1의 이벤트 목록에는 인수인계가 한가람 → 윤바다 1건뿐이다. 그대로 두면 03-plan·01-requirements의 검증 기준과 맞지 않는다.

| 기준 | 요구 | 이벤트 1건만 있을 때 |
|---|---|---|
| R-05 ⑤·D-08 규칙 ①, T-11 | 같은 업무에서 인수인계가 2회 이상이어야 "매번 인수인계 반복"이 검출됨 | 검출 불가 |
| T-08 | "대사 확인" → 윤바다가 유사 경험자로 나옴 | D-08이 현재 담당자를 제외하므로, 현재 담당자가 윤바다면 나오지 않음 |
| R-03·T-07 | 윤바다 → 서하늘 초안 | 서하늘이 담당자가 되는 이벤트가 없음 |

**해결(데이터만 추가, 문서 변경 없음):** 윤바다 → 서하늘 인수인계를 2026-09-30에 완료된 것으로 넣었다(E-007, 인수인계서 없음·이전 인수인계서 미참조). 서하늘이 2026-10-01부터 현재 담당자다. 초안은 이 이력을 근거로 나중에 다시 만들 수 있는 것으로 본다.
- 이렇게 하면 세 기준이 모두 만족된다. 다르게 하려면(예: 인수인계 예정 상태를 이벤트로 표현) 12.2 이벤트 유형 변경이라 CR이 필요하다.
