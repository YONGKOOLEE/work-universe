# 가져오기·내보내기 사용 가이드 (T-17)

- 대상: 업무 유니버스를 직접 써 보고 확인하는 사람
- 기준: 2026-10-03 구현(다섯 번째 검토 V-1·V-3·V-6·V-9~V-11·D3-33 반영 뒤), 2026-10-17 화면 이름 대조(「규모」, 표준 양식 줄, 작성 주체 안내). 최신 커밋은 docs/.status 참조, 변환 규칙 v1(02-design 12.9.1)
- 한 줄 요약: 업무정의서를 붙여 넣으면 규칙으로 읽어 **유니버스 초벌**을 만들고, 사람이 미리 보기로 확인한 뒤 가져온다. 유니버스는 JSON 파일로 내보내고 다시 가져올 수 있다.

---

## 1. 여는 곳

| 화면 | 버튼 | 탭 |
|---|---|---|
| 유니버스를 연 화면 | 머리글 **「가져오기·내보내기」** | 문서 붙여넣기 / JSON 파일 / 내보내기 |
| 시작 화면 | **「문서·파일 가져오기」** | 문서 붙여넣기 / JSON 파일 (내보내기 없음) |

## 2. 문서를 유니버스로 바꾸기

1. 「문서 붙여넣기(초벌 변환)」 탭에서 문서를 붙여 넣는다.
   - 또는 「파일 열기」로 .md·.txt 파일을 고른다.
   - 시험할 때는 **「예시 문서 넣기」**를 누른다(카드승인 업무정의서 원문).
2. **「초벌 변환」**을 누르면 아래에 미리 보기가 나온다.
3. 미리 보기에서 **이름**을 확인하고, **작성 주체**를 입력한다.
   - 원문에 작성 주체가 없으면 빈칸이다. 빈칸이면 「가져오기」가 꺼져 있다.
4. **「가져오기」**를 누르면 저장되고 그 유니버스가 열린다.
   - 「가져오기」를 누르기 전에는 아무것도 저장되지 않는다.

## 3. 미리 보기 읽는 법

| 항목 | 뜻 | 볼 것 |
|---|---|---|
| 규모 | 유형별 노드 수, 연결 수, 메모 수 | 예시 문서는 노드 18, 연결 21, 메모 8 |
| 세분화 | 노드 수가 목표(10~20개, 월말 정산 수준) 안인지 | "많음"이나 "적음"이면 원문 구조를 확인 |
| 원문 근거 | 원문 절 번호(`§3` 등)가 붙은 노드 수 | 문서 변환이면 항상 전체여야 함 |
| 표시 보존 | `[미확인]`·`[가정]`이 붙은 노드 수 | 원문의 표시가 빠지지 않았는지 |
| 노란 글 목록 | 변환하며 생긴 알림 | 아래 6절 참고 |
| 원문의 절 → 유니버스 | 원문 절마다 무엇이 되었는지 | 「규칙 밖」 표시는 규칙에 없는 제목이라 주제로 만든 것 |
| 노드 / 메모 | 만들어질 노드와 메모 목록 | 상태 표시(미확인·가정)와 원문 번호 |
| 표준 양식 | 「표준 양식: 업무 n개 중 m개에 권장 항목이 비어 있음(가져오기는 됩니다)」 — 눌러 펼치면 업무별 빈 항목 | 알림만, 가져오기는 막지 않음(R-16) |
| 빨간 글 | 가져올 수 없는 이유(작성 주체만 비었으면 빨간 글 대신 노란 안내로 위의 「작성 주체」 칸을 채우라고 알림) | 고쳐야 「가져오기」가 켜짐 |

미리 보기에서 고칠 수 있는 것은 **이름과 작성 주체뿐**이다. 나머지는 가져온 뒤 일반 편집(수정·연결 추가·숨기기)으로 고친다.

## 4. 문서를 이렇게 쓰면 잘 바뀐다

### 4.1 읽을 수 있는 형식 (마크다운)

| 원문 표기 | 읽는 방법 |
|---|---|
| `# 제목` (문서 첫 제목) | 문서 이름(업무명이 없을 때) |
| `## 1. 개요`, `### 4.1 예외 처리` | 절. 번호는 원문 근거 `§1`, `§4.1`이 된다 |
| `\| 항목 \| 내용 \|` 표 | 줄마다 한 항목. 머리글이 있으면 "머리글: 값"으로. 이름 칸은 절마다 다르게 고른다 — 범위: `업무`·`업무명`·`작업`·`작업명`·`항목`, 사람: `역할`·`담당`·`담당자`·`이름`, 산출물: `산출물`·`산출물명`·`문서`·`이름`. 그런 칸이 없고 첫 칸 머리글이 `구분`·`순서`·`번호`·`단계`면 그다음 칸을 이름으로 쓴다(미리 보기에 알림). `단계 \| 내용` 표의 번호 칸은 절차에 넣지 않는다 |
| `1. …` 번호 목록 | 단계·질문 번호 |
| `- …`, `* …` 글머리표 | 항목 |
| `> …` 인용 | 머리말(유니버스 설명) |

### 4.2 절 제목으로 정해지는 것

제목의 괄호 안 글자는 보지 않는다. 위에 있는 규칙이 먼저 적용된다.

| 제목에 들어 있는 말 | 무엇이 되나 |
|---|---|
| 산출물, 결과물, 제출물, 양식, 서식 | 산출물 노드 |
| 미확정, 질문, 확정할, 확인할, 리스크, 위험, 이슈 | 메모(질문은 「이슈」, 리스크·위험은 「주의사항」) |
| 흐름, 절차, 프로세스, 처리 순서 | 대표 업무의 **절차 속성**(노드 아님) |
| 이해관계자, 관계자, 역할, 담당자 | 역할(사람) 노드. 표의 하는 일 칸을 쉼표로 나눈 항목이 업무 이름과 같으면 담당 연결 |
| 범위 제외, 범위 외, 범위 밖, 제외, 제외 사항·대상·항목, 비범위, (적용) 대상 외 — **제목 전체가 이 말일 때만** | 유니버스 설명(업무 노드를 만들지 않음). 「장비 범위」·「수수료 제외 기준」처럼 다른 말이 섞이면 해당 없음 |
| 범위, 대상 업무, 업무 목록 | 업무 노드 |
| 개요, 요약, 기본 정보 | 꼭지(이름·목적·배경) |
| 그 밖 | 절 하나가 **주제 노드 하나**(항목은 설명에). 요건·예외·보안·비기능은 하위 유형이 붙고, 나머지는 「규칙 밖」 |

### 4.3 개요에서 읽는 키

개요 표의 2칸 행이나 `- 키: 값` 줄에서 읽는다.

- 업무명, 목적, 배경
- 범위, 범위 제외(범위 외), 이해관계자(담당·담당자도 사람으로 읽음)
- 작성일(`2026-09-15`, `2026.09.15`, `2026. 9. 15.`, `2026년 9월 15일`, `2026/9/15` 모두 읽음. 버전 번호 `v2026.1.2`, 전화번호·긴 번호의 일부, 없는 날짜 `2026.2.31`은 날짜로 보지 않음. 제목·머리말에서는 `작성일`·`기준일`·`일자` 바로 뒤 날짜를 먼저 읽고, `제2026-1-5호`·`문서번호 …` 자리는 날짜로 보지 않음). 주기·마감이 두 번 나오면 먼저 나온 값을 쓴다, 작성 주체(작성자·주관 부서도 됨)
- 주기, 마감, 사용 시스템, 주의사항 → 대표 업무 속성

### 4.4 잘 바뀌는 최소 양식

```markdown
# 가상 신입 교육 운영 업무정의서

- 업무명: 가상 신입 교육 운영
- 목적: 신입 직원이 첫 달 안에 기본 업무를 익히도록 교육을 운영한다.
- 작성 주체: 가상교육팀
- 작성일: 2026-09-15

## 업무 범위
- 강의실 예약
- 강사 섭외

## 진행 순서
1. 입사 예정 인원을 받는다.
2. 강의실과 강사를 확정한다.

## 이해관계자
| 역할 | 하는 일 |
|---|---|
| 교육 운영 담당 | 일정·출석 관리 |

## 운영 규칙
- 강의실 예약은 2주 전까지 끝낸다. [가정]

## 확인할 질문
1. 원격 참여자에게도 만족도 조사를 보내는가?

## 산출물
1. 교육 일정표
2. 출석부
```

### 4.5 한글·워드에서 복사한 문서 (마크다운 표시가 없을 때)

| 원문 표기 | 읽는 방법 |
|---|---|
| 첫 줄 | 문서 제목 |
| `1. 개요`, `2. 업무 절차` | 절 제목. 번호가 차례대로(1 → 2 → 3)일 때만. 문장(…다.)이면 목록 |
| `4.1 예외 처리` | 절 제목(원문 §4.1) |
| `가. 강의실 기준`, `나. …` | 소제목(원문 §5-가). 그 절 안에서 차례대로일 때만 |
| `■ 개요`, `【개요】` | 절 제목 |
| `□ ○ ● ▪ ※ -` | 글머리표. `□ 업무명: …`처럼 "키: 값"이면 개요 항목 |
| `1)`, `(1)`, `①` | 번호 목록 |
| 탭으로 나뉜 줄(워드·한글 표 복사) | 표. 첫 칸이 구분·항목·역할·리스크·ID·작업ID·코드 등이면 그 줄은 머리글 |
| `주의사항`·`유의사항` 절 | 대표 업무의 주의사항 속성 |

- 산출물 절 아래의 `1. 교육 일정표`처럼 번호가 다시 1부터 시작하면 제목이 아니라 목록으로 읽는다.
- 소속 속성은 앞 낱말이 기관처럼 보일 때만 붙는다(A사, 당사, 카드사/VAN, …팀). "교육 운영 담당"의 "교육"은 소속으로 보지 않는다.

## 4-1. 업무는 이렇게 넣는다 (표준 양식)

한 줄 요약: **처리 단계는 노드로 쪼개지 말고 업무 노드의 「절차」에 ①②③으로 적는다.** 월말 정산 점검(업무 3개, 노드 10개)이 카드승인 전문 송수신(처리 단계마다 노드, 38개)보다 보기 편하다는 조력자 의견에 따랐다.

업무 노드마다 이 항목이 있으면 인수인계가 됩니다(없어도 저장은 되고, 화면에 "권장 항목 n개 비어 있음"으로만 알립니다).

| 항목 | 어디에 적나 | 예 |
|---|---|---|
| 설명 | 설명 칸 | 점검 결과를 정리해 보고한다 |
| 절차 | 속성 「절차」 | ① 점검표 결과를 한 장으로 요약 ② 불일치 건과 조치 계획을 기재 ③ 팀장 검토 후 공유 |
| 주기 | 속성 「주기」 | 매월 |
| 마감 | 속성 「마감」 | 월 마감 후 5영업일 이내 |
| 주의사항 | 속성 「주의사항」 | 불일치 건은 원인 확인 전에도 건수와 금액을 먼저 보고한다 |
| 관련 문서 | 속성 「관련 문서」, 또는 산출물 노드를 이어도 됨 | 월별 점검 결과 보고서 |
| 담당 | 「이력 추가」의 담당 시작(수행 연결이 함께 만들어짐) | 사람 → 업무 |

- 좋은 예: 업무 하나에 위 항목이 모두 있고 단계는 절차에 번호로 적혀 있다.
- 나쁜 예: 「요청 검증」「응답 수신」처럼 한 단계씩 노드를 만들고, 각 노드에 주기·마감이 없다(노드가 늘어 한눈에 읽기 어렵다).
- 표로 여러 업무를 한 번에 넣을 때는 열 이름을 「유형, 이름, 설명, 속성」으로 하고 속성 칸에 「절차=①…; 주기=매월; 마감=…」처럼 씁니다(「노드 추가」 → 「표로 추가」).

## 5. JSON 파일과 내보내기

- **내보내기:** 「내보내기」 탭 → 「JSON 파일로 내려받기」를 누르면 `이름-ID.json` 파일을 받는다.
  - 브라우저 저장은 그 PC의 그 브라우저에만 남는다. 다른 PC로 옮기거나 백업할 때 쓴다.
  - **백업 권유:** 마지막 내보내기 뒤 변경이 30건을 넘거나(내보낸 적이 없을 때도 같다), 내보낸 지 7일이 지나고 그사이 바뀐 것이 있으면 머리글 아래에 「내보내기를 권합니다」 줄이 나온다. 「지금 내보내기」를 누르면 파일을 받고 줄이 사라진다. 「닫기」를 누르면 그 시각부터 다시 센다. 지금 연 유니버스의 변경만 센다(2026-10-13, R-21).
- **가져오기:** 「JSON 파일」 탭에서 파일을 고르거나 내용을 붙여 넣고 「확인」 → 미리 보기 → 「가져오기」.
  - 같은 ID의 유니버스가 이미 있으면 덮어쓸지 묻는다. 덮어쓰면 그 유니버스에 고친 내용은 사라진다.
  - 형식이 깨진 파일이나 형식 버전이 다른 파일은 가져오지 않고 이유를 보여 준다.
  - 묶음 유니버스(팀·부서)만 가져오면 그 아래 유니버스가 없다고 알린다. 하위 유니버스 파일도 함께 가져와야 한다.

## 6. 참고할 특이점

### 6.1 꼭 알아야 할 것

1. **한글(HWP)·워드에서 복사한 문서도 읽는다(2026-10-03 추가, 4.5절).** 다만 모양이 아주 다르면 절을 놓칠 수 있으니 미리 보기의 「원문의 절 → 유니버스」 표를 꼭 본다.
2. **「가상 데이터 초기화」를 누르면 가져온 유니버스도 지워진다.**
   - 초기화는 샘플만 남기고 직접 만들거나 가져온 유니버스를 모두 지운다. 필요하면 먼저 내보낸다.
3. **사번은 만들지 않고, 담당(수행) 연결은 원문에 근거가 있을 때만 만든다.**
   - 이해관계자 표의 하는 일 칸(또는 "역할: 하는 일")을 쉼표로 나눈 항목이 업무 이름과 **같을 때만** 그 역할 → 업무 담당 연결을 만든다(결정 D3-33). 표에 「하는 일」(또는 담당 업무) 칸이 있으면 그 칸만 보고, 괄호와 끝 마침표는 떼고 비교한다("승인(1차)" = 승인). "결과 승인", "승인취소 결재"처럼 업무 이름이 일부만 들어간 항목은 잇지 않는다. 메모 "규칙 기반 추정"이 붙고, 미리 보기에 건수가 나온다.
   - 기간이 없어서 '지금 담당'으로 계산된다. 실제 담당 기간은 가져온 뒤 연결을 고쳐 넣는다.
   - 근거가 없으면(예시 카드승인 원문처럼 역할 이름만 있으면) 담당이 없다. 이때 인수인계 초안 대부분이 「이력 부족」, 밀집·공백이 「데이터 부족」으로 나온다.
   - 실제 담당자(사람 이름·사번·기간)는 가져온 뒤 사람 노드를 만들고 「연결 추가」 → 「수행」으로 넣는다.
4. **실제 이름·번호를 넣지 않는다.** 변환 결과에 한글 2~4자뿐인 사람 이름(담당·팀장·강사 같은 역할 낱말 없음)이나 6자리 이상 숫자(이름·사번·설명·속성)가 있으면 미리 보기가 알린다(막지는 않는다. 금액·날짜 숫자도 걸릴 수 있다). 가져오기 전에 역할 이름(예: 정산 담당)과 `V-0000` 형식으로 바꾼다.
5. **같은 문서를 두 번 가져오면 유니버스가 두 개 생길 수 있다.**
   - 변환할 때마다 새 ID가 붙어 "같은 ID" 확인에는 걸리지 않는다.
   - 대신 이름·단위가 같은 유니버스가 있으면 미리 보기에 알리고, 「가져오기」를 누를 때 한 번 더 묻는다(2026-10-03 추가).

### 6.2 변환 결과의 버릇

- **대표 업무는 범위의 첫 항목이다.** 업무 흐름 단계와 개요의 주기·마감 등은 모두 이 업무에 붙는다. 범위 순서가 다르면 엉뚱한 업무에 붙는다.
- **연결은 낱말로 추정한다.**
  - 주제 내용에 업무 이름이 나오면 업무 → 주제로 잇는다.
  - 역할 이름의 핵심 낱말(예: "보안 담당"의 보안)이 주제 이름과 겹쳐도 잇는다.
  - 이 연결에는 "규칙 기반 추정" 메모가 붙는다.
  - "승인"처럼 짧은 업무 이름은 거의 모든 주제와 이어질 수 있다(주제 연결만. 담당 연결은 이름이 같을 때만 만든다).
- **메모가 붙는 곳:** 내용에 업무 이름이 나오면 그 업무, 아니면 꼭지에 붙는다.
- **같은 이름의 범위 항목은 하나로 합쳐진다.** 표에서 이름 칸을 잘못 읽으면(예: 머리글 없는 `일일 | 입고 접수` 표) 업무가 줄어든다. 미리 보기의 노드 목록에서 업무 수를 확인하고, 표에 머리글(`구분 | 업무 | 설명`)을 넣는다. 이름 칸이 빈 행은 건너뛰고 알린다.
- **범위 절의 표는 개요(「키: 값」)로 읽지 않는다.** 구분 칸 값이 「주기」「마감」이어도 업무로 읽는다(2026-10-04 수정). 범위 절 안의 글머리표 `- 주기: 매월`은 지금처럼 대표 업무 속성.
- **절차 번호 바로 아래 들여쓴 글머리표는 그 단계 글에 붙는다**(단계 번호가 밀리지 않음). 범위·질문 절의 들여쓴 글머리표는 따로 읽는다.
- **이름이 없는 항목은 만들지 않고 알린다.** `[미확인]`·`[가정]` 표시만 있거나, 번호·괄호뿐인 이름(`## 3.`, `(양식)`)은 노드가 되지 않고 미리 보기에 「이름이 없어 노드로 만들지 않았습니다」로 나온다(C-NO-NAME).
- **절차 표 `| 단계 | 내용 | 담당 |`**는 「내용 — 담당: 값」으로 적는다.
- **이해관계자 이름 나누기:** "당사 운영·보안·정산 담당"은 역할 셋으로 나뉜다. 기관 이름(A사, 당사 등)은 조직 노드가 아니라 「소속」 속성이 된다. "외부·내부·일부"는 기관으로 보지 않는다.
- **같은 유형·같은 이름은 하나로 합친다.** 원문 근거는 `§1, §2`처럼 이어 붙는다.
- **작성일이 없으면** 메모 날짜가 변환한 날이 된다. 이 때문에 흐름 변화 인사이트는 「한 달 안의 이력 → 데이터 부족」으로 나온다.
- **한 절에 두 성격을 섞으면** 제목의 앞쪽 규칙으로 분류된다. 예를 들어 "업무 범위 및 절차"는 절차로 분류되어 범위 업무가 빠진다. 절을 나누어 쓴다.
- **글 길이 제한:** 2000자를 넘는 설명은 자르고 알린다. 문서 전체는 20만 자, JSON은 500만 자까지 받는다.

### 6.3 생성 방식과의 관계

- 「생성 방식」이 사전 생성이어도 새 문서에는 미리 만든 결과가 없다. 그래서 규칙 기반으로 바꾸고, 미리 보기에 안내 한 줄을 보여 준다(실패가 아님).
- Claude API·사내 LLM을 고르면 연결되어 있지 않아(P2) 규칙 기반으로 바꾸고, 노란 글로 이유를 보여 준다.

### 6.4 샘플과의 관계

- 내장 샘플 「대형가맹점 A 카드승인 전문 송수신」(U-K1, 노드 38개)은 개발 중 더 잘게 변환해 둔 것이다. 같은 원문을 앱에서 초벌 변환하면 노드 18개로, 모양이 다르다.
- U-K1은 그대로 둔다(결정 D3-19, 2026-10-03). 앱 초벌 변환 결과와 비교하는 자료로 쓴다.
