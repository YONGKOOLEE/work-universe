## 1. 1차까지 된 것

업무 유니버스는 한 HTML 파일(`file://` 더블클릭)로, 가상 데이터만 써서 업무 지도 탐색·기록·인수인계 초안(근거 연결, 사람이 확정)·인수인계 위험 등 인사이트·업무 지도 묶기(사번 기준 통합)·편집 되감기·폴더 연결·표로/글로 추가·선택 기능인 실시간 Claude API(가짜 응답으로만 검증)를 한 화면에서 보인다. 사용자의 원래 불만("메뉴찾기가 어려웠고 썼던게 어딨는지 헷갈림", HANDOFF 1절 2026-10-26)에서 시작해 CR-21 기능 찾기와 CR-22 목적별 작업 공간 5개·요약 먼저 항목 카드·단계 표시 그래프·성공 알림·기록 내용 찾기(X-33)까지 넣었다. 열한 번째 전체 검토(2026-10-26)는 차단·높음 0, 인수 기준 174개 중 충족 155이고 미충족 R-ID는 R-10 제출물(사용자 몫)뿐이다. 에이전트 처음 사용 점검 6회차에서 담당 넘기기가 33걸음 → 7걸음, 초안까지 5걸음이 됐다(review-2026-10-26 4절). 단위 시험은 2125개(커밋 9de4f8d 기록). 실제 사람 관찰·실제 API 호출은 아직이다.

## 2. 출발점 — 사용자가 정한 방향

- 원래 불만: "메뉴찾기가 어려웠고 썼던게 어딨는지 헷갈림 … 직관적인지"(HANDOFF 1절 2026-10-26).
- D 시제품을 본 뒤: "지금이게 훨씬 나은데? 여기에 abc까지 포함하고 하면 좋을거 같고 이방향으로 더 개선하면 좋을거 같은데 각 노드별 가독성도 높이는 방향으로"(.status approvals).
- 그래서 단계 2는 CR-22의 설계 원칙(목적이 길 · 요약 먼저·개수로 접고·최신이 위 · 한 기능 한 이름 한 자리 · 규모 전제 · 했으면 보인다 · 색만으로 말하지 않는다, CR-22 2절)을 그대로 잇는다. 원칙을 바꾸는 개선은 이 문서의 범위가 아니다.
- 「쓴 것 찾기」(FU6-4, 사용자 불만의 핵심)는 1차에서 기록 낱말 찾기(X-33: 최대 8건, 두 글자 이상 일치)로 첫 답을 넣었다. 실제 사람이 이 길을 찾는지는 단계 1에서 먼저 본다.
