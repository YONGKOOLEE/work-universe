## AI 활용

**개발 과정.** 설계·구현·검증 전 과정을 Claude Code로 진행했습니다. 계획 문서(착수·요구사항·설계·계획)를 먼저 사람이 승인하고, 그 기준으로 작업을 하나씩 구현·검증했습니다. 저장소 기록으로 확인되는 결과는 단위 테스트 523개, 로컬 커밋 82건, 전체 검토 7회입니다(2026-10-13 갱신). 검토마다 하위 에이전트가 화면·코드·문서를 나눠 읽었고, 확인된 결함은 고친 뒤 다시 검증했습니다.

**제품 안에서의 AI 역할.** 판단의 중심은 규칙입니다. 규칙이 이력에서 근거를 찾고, 문장은 개발 중에 Claude가 미리 써 두었습니다. 모든 문장에는 근거 노드 ID가 붙고, 앱이 그 근거가 실제로 있는지 검증합니다. 근거가 없거나 어긋난 문장은 버리고 규칙 기반 문장으로 바꿉니다. 이력이 없는 항목은 지어내지 않고 「이력 부족」이라고 표시합니다. 초안은 늘 「초안」이며, 사람이 확인해 확정합니다. 화면에는 문장이 「사전 생성」인지 「규칙 기반」인지 표시됩니다.

**실시간 호출을 넣지 않은 이유.** 제출물은 메일로 보내 `index.html`을 더블클릭하면 열려야 하는데, 키를 파일에 넣으면 유출·과금 위험이 있습니다. 그래서 키 없이 동작하는 사전 생성과 규칙 기반을 기본으로 했습니다.

**다음 단계.** 실시간 Claude API·사내 LLM을 꽂는 연결부와 공급자 자리는 이미 있고, 비어 있습니다. 연결해도 근거 검증과 규칙 기반 대체는 그대로 적용됩니다. 실데이터를 쓰려면 사내 보안 검토가 먼저 필요합니다(전환 경로 문서 참고).

| 단계 | AI가 하는 일 | 사람이 하는 일 |
|---|---|---|
| 개발 | Claude Code가 설계 초안·구현·테스트·결함 검토 | 계획 승인, 결과 확인 |
| 문장 준비 | Claude가 근거 목록을 읽고 문장 작성(개발 중) | 문장 검토 |
| 실행 중 | 규칙이 근거 검색, 앱이 근거 ID 검증, 불일치는 규칙 기반 대체 | 초안 확인·확정, 인사이트 해석 |
| 이력 없음 | 「이력 부족」·「데이터 부족」 표시 | 입력 보강 |
