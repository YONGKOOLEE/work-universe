## 1. 제목과 한 줄

**업무 유니버스 — 담당자가 바뀌어도 끊기지 않는 업무 지도**

기록에서 **근거가 달린 인수인계 초안**과 **"혼자만 아는 업무" 경고**를 자동으로 만듭니다. 설치·서버·API 키 없이 파일 하나로 동작하고, 모든 데이터는 가상입니다.

## 2. 문제

- 인수인계는 대부분 전임자의 기억과 구두 설명에 기대고, 떠난 뒤에는 물어볼 곳이 없습니다.
- 업무 지식이 문서·메신저·개인 메모에 흩어져 있어 "누가 무엇을 어떻게 해 왔는지"를 조직이 조망할 수단이 없습니다.
- 같은 설명을 담당자가 바뀔 때마다 처음부터 반복하고, 같은 문제가 다른 팀에서 되풀이되어도 알아채지 못합니다.

## 3. 아이디어

**업무 하나 = 작은 지도 하나.** 업무·사람·산출물·주제를 노드로, 담당·산출·선후행·참조를 연결로 두고, 담당 시작·종료·인수인계·메모를 **이력**으로 쌓습니다. 기록은 지우지 않고(숨김과 되감기만) 쌓이며, 팀·부서는 작은 지도를 **묶어서 접어** 봅니다 — 부서 샘플은 노드 75개 중 처음 화면에 18개만 보입니다.

## 4. 핵심 기능

| | 기능 | 한 줄 |
|---|---|---|
| ① | **근거 달린 인수인계 초안 → 확정** | 10개 항목(개요·절차·일정·주의사항·진행 중·산출물·관계자·최근 이슈·이전 인수인계·유사 경험자). 문장마다 근거 노드·이력이 붙고, 근거가 없으면 지어내지 않고 「이력 부족」. 사람이 확정하면 인수인계서가 되어 다음 인수인계의 근거가 됩니다. |
| ② | **인수인계 위험 인사이트** | 한 사람만 해 봤고 인수인계 기록이 없는 업무(「높음」), 업무별 인수인계 준비도(6항목 중 몇 개), 막히면 함께 멈추는 길목 업무와 혼자 맡은 사람. 유사 경험자·반복 비효율·밀집/공백·흐름 변화와 함께 모두 근거를 보여 줍니다. |
| ③ | **편집 되감기** | 지도가 언제 어떻게 고쳐졌는지 시점을 골라 그때 모습을 읽기 전용으로 보고, 되돌릴 수 있습니다. 되돌림도 이력으로 남아 다시 되감을 수 있습니다(저장 방식 변경 없이 이력을 거꾸로 적용). |
| ④ | **각자 만들고 묶기** | 사번이 같은 사람은 자동으로 잇고, 비슷한 업무는 점수와 이유를 붙여 **사람이 확인**합니다(자동으로 합치지 않음). 공유 폴더에 각자 파일을 두면 서버 없이 팀 지도로 묶입니다. |

## 5. AI 활용

**개발 전 과정.** 설계·구현·검증을 Claude Code로 진행했습니다. 계획 문서(착수·요구사항·설계·계획)를 사람이 승인하고, 작업마다 테스트를 먼저 쓴 뒤 구현했습니다. 큰 변경은 하위 에이전트가 범주별로 검토하고, 고친 뒤에는 수정 전 판과 나란히 돌려 회귀를 잡았습니다(전체 검토 9회).

**제품 안에서.** 판단의 중심은 규칙입니다. 규칙이 이력에서 근거를 찾고, 문장은 개발 중에 Claude가 **그 근거만 보고** 미리 썼습니다. 앱은 열 때마다 근거 ID가 실제로 있는지와 근거 내용의 지문이 쓸 때와 같은지 검증해, 근거가 사라지거나 바뀐 문장은 규칙 기반 문장으로 바꿉니다. 화면에는 문장마다 「사전 생성」인지 「규칙 기반」인지 표시됩니다. 초안은 늘 초안이며 사람이 확정합니다.

**실시간 호출을 넣지 않은 이유.** 제출물은 심사 PC에서 더블클릭(또는 URL)으로 바로 열려야 하는데, 파일에 키를 넣으면 유출·과금 위험이 있습니다. 그래서 키 없이 동작하는 사전 생성과 규칙 기반을 기본으로 했습니다.

**다음 단계.** 실시간 Claude API·사내 LLM을 꽂는 연결부와 공급자 자리는 이미 있습니다. 바뀌는 것은 셋입니다. ① 규칙 기반 결과를 먼저 보여 주고 LLM 문장이 오면 항목 단위로 교체 ② LLM에는 규칙이 고른 근거만 보내고, 응답 문장마다 근거 ID와 **원문 인용 구절**을 요구해 앱이 그 구절이 근거에 있는지까지 검증 ③ 결과는 근거 지문을 키로 저장해 데이터가 바뀌지 않으면 다시 부르지 않음. 호출이 실패하거나 오프라인이면 지금처럼 규칙 기반으로 동작하므로, LLM은 문장을 다듬는 역할에 머물고 판단과 안전장치는 규칙에 남습니다. 업무정의서처럼 모양이 제각각인 문서를 지도로 바꾸는 일도 같은 자리에서 AI 변환으로 넓힙니다.

## 6. 확산

- **설치·서버·로그인 없음.** `index.html` 하나를 더블클릭하면 열립니다. 〔URL: 사용자 결정〕
- **시작은 업무 이름 하나.** 「내 업무를 정리해 두고 싶어요」에 업무 이름만 넣으면 작은 지도가 생기고 「처음 할 일」이 안내합니다. 스프레드시트 표 붙여넣기, 업무정의서 초벌 변환으로 한 번에 넣을 수 있습니다.
- **각자 → 팀 → 부서.** 내보낸 파일이나 **폴더 연결**(공유 폴더에 각자 파일을 두면 앱이 읽어 묶음)로 서버 없이 확장합니다. 내용을 담은 HTML 파일 하나로 받는 사람에게 그대로 보여 줄 수도 있습니다.
- **다음.** 조직 전체로 가려면 저장 계층만 서버·DB로 바꾸면 됩니다. 묶기·접기·통합 확인 구조는 그대로입니다.

## 8. 구조와 검증 (코딩 난이도)

- **순수 함수와 화면의 분리:** 데이터 모델·검증·명령, 화면 계산, 통합 판정, 규칙(초안·인사이트·변환), AI 연결부는 브라우저 기능을 쓰지 않는 모듈(약 절반)이고 Node에서 단위 테스트합니다. 화면·저장소는 별도 계층이라 저장 방식을 바꿔도 핵심 로직은 그대로입니다.
- **이력 역적용 되감기:** 모든 변경이 변경 전·후 값과 함께 이력으로 남아, 어느 시점의 지도든 이력을 거꾸로 적용해 다시 만듭니다. 되돌리기는 기존 명령(숨김·되살림·수정)만 묶어 적용해 기록을 지우지 않습니다.
- **근거 검증과 지어내지 않기:** 모든 생성 문장은 근거 ID·지문 검증을 거치고, 실패하면 규칙 기반으로 대체합니다. 규칙 변환기는 108개 경계 사례를 고정 비교로 지킵니다.
- **단일 HTML 빌드:** 외부 CDN 없이 라이브러리를 함께 묶어 `file://`에서 동작하고, 빌드가 모듈·외부 요청 금지 규칙을 검사합니다.
