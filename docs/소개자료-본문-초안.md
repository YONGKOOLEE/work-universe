## 1. 제목과 한 줄

**업무 유니버스 — 담당자가 바뀌어도 끊기지 않는 업무 지도**

기록이 쌓이는 **업무 지도**에서 **근거가 달린 인수인계 초안**과 **"혼자만 아는 업무" 경고**를 자동으로 만듭니다. 설치·서버 없이 파일 하나로 열리고, 본인 Claude API 키를 넣으면 실시간 AI가 켜집니다(키가 없어도 모든 기능이 동작). AI가 쓴 내용은 앱이 원문 인용까지 검증해 통과한 것만 보여 줍니다. 모든 데이터는 가상입니다.

## 2. 문제

- 인수인계는 대부분 전임자의 기억과 구두 설명에 기대고, 떠난 뒤에는 물어볼 곳이 없습니다.
- 업무 지식이 문서·메신저·개인 메모에 흩어져 있어 "누가 무엇을 어떻게 해 왔는지"를 조직이 조망할 수단이 없습니다.
- 같은 설명을 담당자가 바뀔 때마다 처음부터 반복하고, 같은 문제가 다른 팀에서 되풀이되어도 알아채지 못합니다.

## 3. 아이디어

**업무 하나 = 작은 지도 하나.** 업무·사람·산출물·주제를 노드로, 담당·산출·선후행·참조를 연결로 두고, 담당 시작·종료·인수인계·메모를 **이력**으로 쌓습니다. 기록은 지우지 않고(숨김과 되감기만) 쌓이며, 팀·부서는 작은 지도를 **묶어서 접어** 봅니다 — 부서 샘플은 노드 75개 중 처음 화면에 18개만 보입니다.

## 5. AI 활용

**① 개발 전 과정.** 설계·구현·검증을 Claude Code로 진행했습니다. 계획 문서(착수·요구사항·설계·계획)를 사람이 승인하고, 작업마다 테스트를 먼저 쓴 뒤 구현했습니다. 큰 변경은 하위 에이전트가 범주별로 검토하고(전체 검토 9회, 실시간 AI 기능은 별도 재검증 1회), 고친 뒤에는 수정 전 판과 나란히 돌려 회귀를 잡았습니다. 검증 코드를 일부러 끈 결함 주입 시험으로 "테스트가 그 결함을 실제로 잡는지"도 확인했습니다.

**② 제품 안의 AI 세 가지 (본인 Claude API 키를 넣으면 실시간).**

| | 어디서 | 무엇을 하나 |
|---|---|---|
| 가 | **인수인계 초안·인사이트 설명** | 규칙이 고른 근거만 Claude에게 보내 문장을 다듬습니다. 사전 생성 문장이 먼저 보이고 「생성 중…」 뒤에 항목 단위로 Claude 문장(칩 「Claude API」)으로 바뀝니다. |
| 나 | **업무정의서 AI 변환** | 규칙 변환이 나누지 못하는 "업무가 여러 개인 문서"(규정집·긴 정의서)를 읽어 업무·사람·산출물·연결의 지도 초벌을 만듭니다. 미리 보기에서 사람이 확인한 뒤 가져옵니다. |
| 다 | **"뜻이 같은 업무" 후보** | 팀·부서를 묶을 때 통합 확인 목록의 「AI로 연관 찾기」가 이름이 달라도 같은 일로 보이는 업무 쌍을 이유·인용과 함께 「AI 후보」로 제안합니다. 「같은 업무」/「다른 업무」는 사람이 정합니다. |

**③ 지어내기를 막는 3중 검증 — 이 제품의 AI 차별점.** AI가 그럴듯한 말을 지어내는 것이 업무 도구의 가장 큰 위험이라, 모델의 답을 그대로 쓰지 않고 앱이 세 겹으로 거릅니다. 그리고 그 결과를 사용자가 **눈으로 확인**할 수 있게 했습니다: 문장 밑 근거 칩을 누르면 그래프에서 근거 노드가 빛나고 그 항목 아래에 **원래 기록 한 줄이 펼쳐집니다**("지어낸 게 아니라 이 기록에서 나온 문장").
1. **구조화 출력 스키마:** 응답은 정해진 JSON 모양만 받습니다. 모양이 어긋나면 응답 전체를 버리고 지금 문장·규칙 결과를 유지합니다.
2. **근거 ID·지문:** 문장이 가리킨 근거 노드·이력이 실제로 있고, 그 내용의 지문이 규칙이 보낸 때와 같은지 봅니다.
3. **원문 인용(quote) 부분 문자열 검증:** 모델은 항목마다 원문에서 따온 인용 구절을 함께 내야 하고, 앱이 그 구절이 **원문(근거 글)에 실제로 들어 있는지** 직접 찾아봅니다(정규화 뒤 8자 이상). 원문에 없는 인용이면 그 항목·후보만 버리고 화면에 **「원문 인용이 확인되지 않아 뺀 항목 n개」** 로 몇 개를 뺐는지 보여 줍니다(초안·설명 문장은 호출 전 문장을 「원래 문장을 유지함」으로 남김).

검증을 통과해도 **확정은 사람**입니다. 인용 검증이 보증하는 것은 "그 구절이 원문에 있다"까지이고, 같은 업무인지·요약이 맞는지는 사람이 판단합니다. 근거 글 안에 "이전 지시를 무시하라" 같은 문장이 섞여 있어도 따르지 않도록 프롬프트에 규칙을 두었습니다.

**④ 키가 없어도 동작합니다.** 규칙이 근거를 찾고, 문장은 **예시 지도의 기록을 앱을 만들 때 Claude에 넣어 미리 받아 둔 문장**입니다(사전 생성, 생성일 2026-10-23). 앱은 열 때마다 같은 검증(근거 ID·지문)을 돌려 근거가 사라지거나 바뀐 문장은 규칙 기반 문장(기록을 그대로 모은 문장)으로 바꿉니다. 사용자가 새로 만든 지도에는 미리 받아 둔 문장이 없어, 키가 없으면 규칙 기반 문장이고 키를 넣으면 Claude가 그 자리에서 씁니다. 화면에는 문장마다 「사전 생성」·「규칙 기반」·「Claude API」 중 무엇인지 표시됩니다. 키가 없으면 「AI로 변환」·「AI로 연관 찾기」 단추는 보이지 않고, 「Claude API」를 골라도 기록을 그대로 모은 문장으로 내려가지 않고 미리 받아 둔 문장(사전 생성)이 그대로 보이며 "키가 없어 미리 받아 둔 문장(사전 생성)으로 보여 줍니다"라는 안내만 나오며(미리 받아 둔 문장이 없는 내가 만든 지도만 규칙 기반 안내)(초안 맨 아래에는 "키를 넣으면 이 초안을 Claude가 새로 씁니다(선택)" 한 줄), 키가 있어도 호출이 실패하거나 시간이 초과되거나 오프라인이면 원인을 보여 주고 이전 문장·규칙 결과로 돌아갑니다. 판단과 안전장치는 규칙에 남고 AI는 문장을 쓰고 후보를 제안하는 역할입니다.

**⑤ 키와 보안.** 제출물에는 키가 들어 있지 않습니다. 심사자가 쓰려면 설정에서 **본인 키**를 넣고, 키는 **이 브라우저 저장소에 암호화 없이** 저장되며 내보낸 파일·내용 포함 HTML·연결한 폴더·이력에는 들어가지 않습니다(테스트로 확인, 「키 지우기」로 삭제하면 받아 둔 응답 캐시도 함께 지워짐). 호출은 `api.anthropic.com`으로만 가고(공식 SDK를 파일 하나에 묶어 사용) 과금은 본인 키 기준입니다. **밖으로 나가는 것**은 키를 넣고 쓸 때의 근거 글(노드 이름·설명·속성·사번, 이력 한 줄)과 변환할 문서 원문이며, 키가 없으면 기록을 어디로도 보내지 않습니다. 이 내용은 앱의 「?」 도움말 「키와 데이터」와 설정 창에 같은 말로 적혀 있고, 실제 업무 기록은 회사의 외부 전송 기준을 확인한 뒤 쓰도록 안내합니다. 문서 변환의 문서 내용은 저장소에 남기지 않고 메모리에만 둡니다. 브라우저에서 키를 직접 쓰는 방식은 공식 문서가 내부 도구·신뢰된 사용자·시연 용도에 한해 쓰도록 경고하는 방식이라, 조직 서비스로 가면 서버 중계로 바꿔야 합니다(9절).

## 6. 확산

- **설치·서버·로그인 없음.** `index.html` 하나를 더블클릭하면 열립니다. AI를 쓰려면 본인 키만 더하면 되고, 안 써도 전부 동작합니다. 〔URL: 사용자 결정〕
- **시작은 업무 이름 하나.** 「내 업무를 정리해 두고 싶어요」에 업무 이름만 넣으면 작은 지도가 생기고 「처음 할 일」이 안내합니다. 스프레드시트 표 붙여넣기, 업무정의서 변환(규칙 초벌, 키가 있으면 AI 변환)으로 한 번에 넣을 수 있습니다. 규칙 변환은 「담당」 절(업무가 하나뿐인 문서에서 담당으로 잇고 추정 알림), 「관련 문서」 절(산출물 노드, 업무가 「참조」로 이음), 산출물 이름 뒤 경로 괄호(속성 「위치」), 작성 줄의 날짜와 「작성:」·「작성 부서:」 줄의 조직 낱말(…팀·…부 등)까지 읽고, 사람이 미리 보기에서 확인합니다.
- **각자 → 팀 → 부서.** 내보낸 파일이나 **폴더 연결**(공유 폴더에 각자 파일을 두면 앱이 읽어 묶음)로 서버 없이 확장합니다. 내용을 담은 HTML 파일 하나로 받는 사람에게 그대로 보여 줄 수도 있습니다.
- **다음.** 조직 전체로 가려면 저장 계층만 서버·DB로 바꾸면 됩니다. 묶기·접기·통합 확인 구조는 그대로입니다.

## 8. 구조와 검증 (코딩 난이도)

- **순수 함수와 화면의 분리:** 데이터 모델·검증·명령, 화면 계산, 통합 판정, 규칙(초안·인사이트·변환), AI 연결부는 브라우저 기능을 쓰지 않는 모듈(약 절반)이고 Node에서 단위 테스트합니다. 화면·저장소는 별도 계층이라 저장 방식을 바꿔도 핵심 로직은 그대로입니다.
- **이력 역적용 되감기:** 모든 변경이 변경 전·후 값과 함께 이력으로 남아, 어느 시점의 지도든 이력을 거꾸로 적용해 다시 만듭니다. 되돌리기는 기존 명령(숨김·되살림·수정)만 묶어 적용해 기록을 지우지 않습니다.
- **AI 응답 검증기:** 초안·문서 변환·연관 후보가 같은 인용 검증 규칙(정규화·길이·글자 수·근거 글 머리 제외)을 한 곳에서 씁니다. 항목 단위로 버리고 연결의 양 끝이 사라지면 연결도 버리며, 화면이 바뀐 뒤 늦게 도착한 응답은 버리고 같은 요청의 중복 호출은 하나로 합칩니다. 재검증에서 인용 우회 시도 23건을 표로 점검했고, 검증 코드를 끄면 테스트가 실패하는지 결함 주입 시험으로 확인했습니다(가짜 응답 도구 기준). 규칙 변환기는 113개 경계 사례를 고정 비교로 지킵니다.
- **키 없는 경로 불변:** 실시간 호출은 별도 비동기 연결부로 더했고, 키가 없을 때의 화면·결과는 이전과 같음을 같은 입력 378건 비교 등으로 확인했습니다(CR-15 시점의 비교이며, 이후 처음 사용 점검에서 키 없음 안내 문구를 다듬었습니다).

## 9. 한계와 다음 단계

- 1차 제출물은 **가상 데이터**로만 동작을 보였고, 저장은 브라우저 저장소(또는 연결한 폴더)입니다. 실데이터 연결과 권한은 사내 보안 검토가 먼저입니다(실사용 전환 경로 문서 별도).
- 유사 경험자의 "이름에 같은 낱말" 후보는 이름이 우연히 겹친 다른 일도 올릴 수 있어(낮은 점수·"같은 일인지 확인" 표시, 결정은 사람), 변환의 담당 잇기는 업무가 하나뿐인 문서에서만 합니다(여럿이면 어느 업무인지 원문에 없음). 개요 첫 문장의 업무 설명화와 문장 속 주기·마감 구절 읽기는 오탐 때문에 넣지 않았습니다.
- 사용성 점검은 에이전트 역할 수행이라 실제 사용자의 막힘을 대신 보증하지 않습니다(7절). 〔실제 사람 대리 관찰 결과: 확인 전〕
- 실시간 AI 세 가지는 가짜 응답 도구로 동작·검증을 점검했습니다. 실제 모델 응답의 품질(인용을 원문 그대로 따오는 정도, 긴 문서의 응답 시간)은 〔사용자가 본인 키로 확인한 뒤 결과 기재 — 확인 전〕. 실제 모델이 표 기호를 떼고 인용하면 그 항목은 검증에서 버려져 변환 항목이 줄 수 있습니다.
- 키는 브라우저 저장소에 평문으로 저장되므로 공용 PC에서 쓰지 않아야 하고, 키가 없어도 외부 호스트로의 연결이 정책(CSP)상 열려 있습니다(알려진 위험은 없으나 한계로 기록).
- 다음 단계: 폴더 연합 확대 → 저장 계층 교체로 조직 전체. 조직에 도입할 때는 키를 브라우저에 두지 않고 서버 중계로 바꾸고, 사내 LLM은 공급자 자리만 있고 아직 연결하지 않았습니다.
