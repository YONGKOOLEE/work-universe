# 시연 영상 대본 초안 (3분, v0.3 반영안)

- 문서명: 시연 대본 초안 v0.3 반영안 · 상태: draft(사용자 확인 전) · 작성 2026-10-05, v0.2 반영안 2026-10-13(CR-12: R-19~R-22, 일곱 번째 검토 5절), v0.3 반영안 2026-10-17(조력자 의견 "시작이 막막하다·커지면 난잡하다" 대응 메시지, 장면 3 문구 정정) · 관련: T-16(영상·소개자료), R-03·R-05·R-14·R-17
- 대상: 영상을 찍는 사용자(말할 내용과 누를 순서). 화면 이름·버튼 이름은 실제 앱 그대로이며, 실행 안내의 "5분 둘러보기"와 같은 길입니다.
- 이 문서는 **초안**입니다. 영상은 기능 동결 뒤에 찍고, 찍기 직전에 아래 "찍기 전 확인"을 다시 해야 합니다.

## 한 줄 메시지
담당자가 바뀔 때 "누가 무엇을 어떻게 해 왔는지"가 사람 머릿속에서만 넘어가던 것을, **기록이 쌓이는 그래프**로 남기고 **인수인계 초안을 근거와 함께** 만들어 준다.

(v0.3) 함께 전할 두 번째 메시지: **조직 전체를 한 장에 그리는 도구가 아니다. 업무 하나씩 작게 그리고, 팀·부서로 묶으면 위에서는 접혀 보인다.** (조력자 의견 "어떻게 시작할지 막막하다", "커지면 그림이 난잡해진다"에 대한 답. 부서 샘플은 노드 75개 중 처음 화면에 18개만 그린다)

## 장면 구성 (v0.2 반영안, 2026-10-13)

3분(180초)을 넘기지 않도록 시간을 다시 나눴다. **줄인 곳(각 -5초):** 장면 1(20→15초, 문제 설명을 한 문장으로), 장면 3(35→30초, 항목 설명 줄임), 장면 5(25→20초). **늘린 곳(각 +5초):** 장면 2(미해결 n건), 장면 4(내려받기 2초 포함), 장면 7(표 붙여 넣기, v0.1의 「예시 문서 넣기」를 대신함). 장면 6은 시간은 그대로이고 설명·속성 찾기 내용만 더했다. 합계 3:00. v0.1의 장면은 지우지 않고 바뀐 곳만 굵게 표시했다.

## AI 활용을 말하는 방법 (심사 항목 대응)
- 규칙이 근거를 찾고, 문장은 개발 때 Claude로 미리 써 두며(사전 생성), **앱이 모든 문장의 근거를 검증**한다. 근거가 없으면 규칙 기반 문장으로 바꾸고, 이력이 없으면 「이력 부족」이라고 쓴다.
- 이 앱 자체도 Claude Code로 설계·구현·검증했다(단위 테스트, 브라우저 점검, 검토 에이전트로 결함을 찾아 고침). 숫자는 영상 직전에 다시 센다: `npm test`의 통과 개수.
- 실시간 호출을 넣지 않은 이유: 키·과금·보안, 그리고 더블클릭만으로 열려야 하는 실행 조건. 연결부는 만들어 두었고 공급자 자리만 비어 있다.

## 찍기 전 확인
1. 가장 새 제출본을 새 프로필(또는 「가상 데이터 초기화」 후)에서 연다. 처음 상태가 아니면 장면 2·5의 숫자가 다르다.
2. 화면 크기 1366×768 이상, 브라우저 확대 100%. 노드 이름이 작으면 마우스를 올리거나 장면 6의 찾기를 쓴다.
3. 장면 4에서 확정하고 장면 7에서 저장하면 데이터가 바뀐다. 다시 찍으려면 「가상 데이터 초기화」. 장면 2에서는 「해결로 표시」를 누르지 않는다(숫자가 바뀐다).
3-1. (v0.2) 장면 4 전에 머리글 「설정」의 「작성자 이름」에 가상 이름을 적는다. 장면 7의 표(가상 업무 2~3행, 탭으로 나눔)는 미리 복사해 둔다. 백업 권유 줄(「내보내기를 권합니다」)이 화면에 떠 있으면 「닫기」로 치운다.
4. 장면 6의 "가상 운영부"는 처음 열 때 통합 확인 대기 건수가 보인다. 업무 후보 첫 항목은 엉뚱해 보일 수 있으니 「통합 확인 목록」을 열고 업무 후보 맨 끝(7번째)의 「장소 섭외 ↔ 강의실·강사 섭외」와 사번 충돌(윤바다/윤바다라)을 보여 준다.
5. 영상 길이·형식·용량 제한은 주최 측 공지로 확인한다(00-context에 미확인으로 남아 있음).
