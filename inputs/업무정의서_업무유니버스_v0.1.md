# 업무정의서 — 업무 유니버스 (Work Universe)

## 1. 프로젝트 개요

- **명칭**: 업무 유니버스 (Work Universe)
- **한 줄 정의**: 조직 안에 흩어진 업무 지식(사람의 기억, 협업툴 문서, 사내 게시물 등)을 하나의 그래프로 연결해, 탐색·문서 생성·인사이트 도출을 지원하는 지식 지도
- **배경**: 업무 지식은 개인의 머릿속, 컨플루언스 같은 협업툴, 사내 홈페이지 문서 등 제각각 다른 위치·형태로 흩어져 있거나 아예 기록되지 않아, 필요할 때 통합적으로 찾거나 연결하기 어렵다. 그 결과 인수인계 품질이 담당자 역량에 따라 달라지고, 유사 경험자나 관련 자료를 찾을 때마다 매번 사람에게 직접 물어봐야 하는 비효율이 반복된다.
- **참고 레퍼런스**: 모소밤부 UNIVERSE(블로그 글 1,054편을 10개 대주제·60여 개 테마로 묶어 노드 클릭 시 관련 글이 펼쳐지는 시각화 구조) — 시각화·탐색 방식의 참고 모델로 활용

## 2. 목표

업무 지식을 사람-업무-산출물 단위의 그래프로 연결해, 다음 세 가지를 지원하는 것을 목표로 한다.

1. 흩어진 업무 지식을 하나의 화면에서 탐색
2. 축적된 이력을 바탕으로 인수인계 등 필요한 문서 초안 자동 생성
3. 그래프 전체를 조망해 조직 차원의 패턴(업무·인력 밀집/공백 영역, 반복되는 비효율 유형, 시간에 따른 업무 흐름 변화)을 파악하고 향후 방향에 참고할 인사이트 제시

## 3. 범위 정의

### 포함 (In-scope, 공모전 프로토타입)
- 사람-업무-기간-소속조직-산출물을 노드/엣지로 표현하는 범용 그래프 데이터 모델
- 가상 데이터 기반 프로토타입(실제 사내 데이터 연동 제외)
- 인터랙티브 그래프 시각화(탐색 기능)
- LLM 기반 인수인계 문서 초안 자동 생성
- 그래프 통계 기반 인사이트 도출(유사 경험자 탐색, 밀집/공백 영역 파악 등)

### 제외 (Out-of-scope, 이번 단계)
- 실제 사내 시스템(인사·조직관리 DB 등)과의 실데이터 연동 — 보안·접근권한 문제로 프로토타입 단계에서는 제외
- 정량적 효과의 확정 수치 제시 — 실측 데이터가 없어 "추정 근거 부족"으로 명시, 프로토타입 검증 후 산정
- 인력배치 등 최종 의사결정의 자동화 — AI는 근거 제시까지만 담당, 최종 판단은 사람이 수행

## 4. 핵심 기능 정의

| 기능 | 입력 | 출력 | 비고 |
|---|---|---|---|
| 업무 지식 탐색 | 그래프 노드/엣지 데이터 | 노드 클릭 시 관련 정보·맥락이 펼쳐지는 인터랙티브 화면 | 모소밤부 UNIVERSE 시각화 방식 참고 |
| 문서 초안 자동 생성 | 특정 인물/업무의 노드 데이터 | 인수인계 문서 등 초안(LLM 생성) | 과거 유사 사례의 반복 누락 항목 경고 포함 |
| 유니버스 단위 인사이트 도출 | 그래프 전체 통계 | 업무·인력 밀집/공백 영역, 반복 비효율 유형, 흐름 변화, 유사 경험자 목록 | 최종 판단은 사람이 수행, AI는 근거 제시까지 |

## 5. 데이터 모델 (범용 스키마 원칙)

- 노드: 담당자, 업무명, 수행 기간, 소속조직, 산출물(문서/링크) — 특정 직무·업종에 종속된 필드는 스키마 자체에 포함하지 않음
- 엣지: 같은 담당자 수행, 선후행/인수인계 관계, 소속 변경(조직개편) 관계, 유사 업무 태그 관계
- 원칙: 실제 업무명·내용은 데이터(인스턴스)로 채우고, 스키마(뼈대)는 조직·업종에 무관하게 동일하게 유지 → 확산가능성 확보의 핵심 근거

## 6. 가상데이터 시나리오 원칙

- 실데이터 접근이 어려운 만큼 가상 인물(약 20~30명), 다부서 구성(예: IT팀 + 영업팀 + 인사팀 등 성격이 다른 2~3개 이상 부서 혼합), 조직개편 이벤트(2~3회) 시나리오로 구성
- 단일 부서로만 시나리오를 채우지 않고 성격이 다른 부서를 혼합해, 같은 스키마가 여러 업무 성격에 동일하게 적용됨을 시연에서 증명

## 7. 기술 스택(안)

- 데이터/그래프 처리: Python, NetworkX
- 시각화: Pyvis 또는 D3.js 기반 인터랙티브 노드맵
- 데모 웹앱: Streamlit 또는 Flask
- 문서 초안 생성: LLM API(프롬프트에 노드 데이터 입력)
- 데이터 저장: CSV/JSON (프로토타입 규모에서는 별도 그래프DB 불필요)

## 10. 보안·리스크 고려사항

- 인사·조직 데이터는 민감정보이므로 프로토타입은 전부 가상데이터로 구성해 리스크 회피
- 실도입 시에는 조직관리팀·인사관리팀으로 접근권한 제한, 개인 열람권한은 본인 이력에 한정하는 정책 필요
