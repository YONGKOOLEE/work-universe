# 업무정의서 v0.2 — 업무 유니버스 (Work Universe)

상태: 사용자 승인 완료(v0.1 → v0.2 변경 5건 전부 승인)
범위: 업무정의 단계. 스키마 필드·기술스택·구현 설계는 확정하지 않음.
표기: [제안]은 사용자가 직접 말하지 않고 대화 중 도출된 항목(이번 승인으로 채택됨). 미확인은 가정으로 표시.

## 1. 개요

- 명칭: 업무 유니버스 (Work Universe)
- 정의: 어떤 업무·조직에도 통하는 **유니버스의 틀과 도구**. 조직 안에 흩어진 업무 지식(사람의 기억, 협업툴 문서, 사내 게시물 등)을 유니버스 단위 그래프로 연결하여 탐색, 문서 초안 생성, 인사이트 도출을 지원하는 지식 지도.
- 유니버스 단위: 업무 하나가 유니버스 하나. 업무 → 팀 → 부서 → 본부 → 회사로, 하위 유니버스를 통합해 상위 유니버스를 구성할 수 있어야 한다.
- 시각화 참고 모델: 모소밤부 UNIVERSE 캡처(노드 클릭 시 관련 주제·글이 펼쳐지는 탐색 화면). 목표 수준의 예시이며 그대로 복제하기로 한 것은 아님.

## 2. 현행 업무와 병목

- 현행 방식: 도제식 운영.
- 병목 1: 업무 지식이 개인 기억, 협업툴(예: 컨플루언스), 사내 홈페이지 문서 등에 흩어져 있거나 기록되지 않아 통합 조회·연결이 어렵다.
- 병목 2: 인수인계 품질이 담당자 역량에 따라 달라진다.
- 병목 3: 유사 경험자·관련 자료를 찾을 때마다 사람에게 직접 물어야 한다.
- 병목 4: 조직 차원의 업무·인력 분포, 반복 비효율, 시간에 따른 흐름을 조망할 수단이 없다(원하는 결과에서 도출, 실측 없음).

## 3. 사용 주체

| 주체 | 역할 | 상태 |
|---|---|---|
| 일반 구성원(팀) | 유니버스 생성, 자료 업데이트, 탐색, 인수인계 초안 생성 | 확인 |
| 인수인계 담당자·인수자 | 초안 검토·확정 | [제안] |
| 조직 관리 역할 | 통합 유니버스·인사이트 참고 | 대상 직무 미확인 |
| 공모전 심사자 | 실행 산출물·시연 영상으로 평가 | 확인 |

## 4. 목표와 성공 판정

- 1차 목표: 공모전 시연 통과. 최종 목표: 실사용.
- 1차 심사: 주제적합성, 실현가능성, 코딩 난이도 등을 감안해 2차 대상 10팀 내외 선정.
- 2차 심사(워크샵): 업무관련성 30, 확산가능성 30, 완성도 20, 창의성 및 AI 활용성 20.
- 성공 판정: 효과 수치 대신, 아래 R-ID별 인수 기준이 시연으로 확인되는지 여부로 판정한다. 효과 수치는 프로토타입 검증 후 산정.

## 5. 범위

포함:
- 가상 데이터 기반의 동작하는 프로토타입(실행 가능한 산출물)
- 유니버스 생성, 자료 추가·수정, 탐색, 인수인계 초안 생성, 유니버스 통합, 조직 인사이트
- 조직관리 유니버스(일반 유니버스로 취급, A 수준)
- 실사용 전환 경로 문서
- 제출물: 실행 가능한 산출물, 시연 영상, 소개자료 1~2쪽

제외:
- 실제 사내 데이터·시스템(컨플루언스, 사내 홈페이지, 인사·조직 DB 등) 연동 [제안]
- 조직관리 유니버스의 기준 데이터 검증 역할(문서 R-09로만 다룸)
- 효과 수치의 확정
- 인력배치 등 최종 의사결정 자동화

MVP: 가상 데이터를 화면에서 탐색하고, 자료를 하나 추가한 뒤 해당 업무 유니버스에서 인수인계 초안을 생성하고, 인사이트 하나를 확인하는 종단 간 흐름. 1차 제출물의 구현 수준이 확인되기 전까지 이 흐름을 최우선으로 한다.

## 6. 사람의 최종 판단 지점

- 인수인계 문서의 확정
- 인사이트의 해석과 활용, 인력배치 결정
- 서로 다른 유니버스의 업무 동일성 연결(자동 병합 금지, 후보 제시 후 사람이 연결)

## 7. 요구사항과 인수 기준

| R-ID | 요구사항 | 조건·입력 | 기대 결과 | 오류 결과 |
|---|---|---|---|---|
| R-01 | 하나의 화면에서 업무 지식 탐색 | 가상 데이터가 로드된 유니버스에서 노드 선택 | 관련 정보와 연결된 노드가 확인됨 | 연결이 없으면 “연결 없음” 표시, 화면 중단 없음 |
| R-02 | 유니버스에 자료 추가·수정 | 사용자가 자료를 입력하거나 변경 | 저장 후 그래프와 탐색 화면에 반영됨 | 필수 정보 누락·중복 시 저장 거부, 사유 표시 |
| R-03 | 담당자 교체 시 해당 업무 유니버스에서 인수인계 초안 자동 생성 | 업무 유니버스와 교체 대상 선택 | 축적된 이력 기반 초안 생성, 근거 노드 확인 가능 | 이력 부족 시 부족 항목 표시, 내용을 만들어내지 않음 |
| R-04 | LLM 없이도 초안 생성 유지 (LLM 사용 가능 여부 미확인) | LLM 미연결 또는 호출 실패 | 규칙 기반으로 초안 생성, 생성 방식 표시 | 대체 동작도 실패하면 원인 표시 |
| R-05 | 단일 또는 통합된 여러 유니버스 대상 인사이트 | 분석 대상 유니버스 선택 | 업무·인력 밀집/공백, 반복 비효율 유형, 시간에 따른 흐름 변화, 유사 경험자가 근거와 함께 제시됨 | 데이터 부족 시 결론 없이 부족 사실 표시 |
| R-06 | 가상 데이터만 사용 | 시연·제출 전 과정 | 실제 사람·업무·사내 정보 없음 | 실데이터 의심 항목은 제출 전 제거 |
| R-07 | 서로 다른 성격의 유니버스에서 같은 틀 동작 | 성격이 다른 여러 유니버스 | 모두 같은 틀로 생성·탐색·생성됨 | 표현 불가 사례는 한계로 기록 |
| R-08 | 사전지식 없이 이용 가능 | 처음 접속한 사용자 | 별도 설명 없이 첫 화면에서 탐색 시작 가능 | 막히는 지점을 사용성 결함으로 기록 |
| R-09 | 실사용 전환 경로 문서 | 문서 작성 | 실데이터 연결, 권한, 보안, 조직관리 유니버스의 기준 데이터 검증 역할이 서술됨 | 미확인 사내 정책은 단정하지 않고 미확인 표기 |
| R-10 | 제출물 완비 | 제출 기한 | 실행 가능한 산출물, 시연 영상, 소개자료 1~2쪽 | 누락은 기한 전에 위험으로 보고 |
| R-11 | 유니버스 통합(필수) | A, B, C팀 유니버스 선택 후 통합 | 사번이 같은 사람은 하나로 연결, 업무는 자동 병합 없이 후보 제시 후 사람이 연결, 결과가 부서 유니버스로 저장·탐색됨 | 사번 없음·충돌 시 자동 판단 없이 사용자 확인 요청 |
| R-12 | 유니버스 생성(필수) | 사용자가 빈 유니버스 생성 | 노드를 구성할 수 있는 새 유니버스가 만들어짐 | 필수 정보 누락 시 생성 거부, 사유 표시 |
| R-13 | 시연용 가상 데이터 구성 [제안] | 데이터 작성 | 성격이 다른 A, B, C팀 유니버스 + 조직관리 유니버스로 구성됨(조력자 작성) | 실데이터 의심·구조 불일치 시 수정 |

## 8. 핵심 시나리오

시연 중심 흐름:
1. A, B, C팀이 각자 유니버스를 만든다. (R-12)
2. 각 유니버스에 자료를 추가·수정하고 탐색한다. (R-01, R-02, R-08)
3. 담당자 교체 시 업무 유니버스에서 인수인계 초안을 생성한다. (R-03, R-04)
4. 세 유니버스를 통합해 부서 유니버스를 구성한다. 사람은 사번, 업무는 사람이 연결한다. (R-11)
5. 부서 유니버스에서 밀집/공백, 반복 비효율, 흐름 변화, 유사 경험자를 확인한다. (R-05)

별도 확인이 필요한 항목: R-07(다른 성격의 유니버스 검증), R-04(LLM 없는 대체 동작, 실패 흐름), R-06·R-09·R-10(문서·제출물 요구)

## 9. 실패·예외 시나리오

- LLM을 쓸 수 없거나 응답이 없다.
- 입력 데이터가 누락되거나 중복이다.
- 이력이 부족한 업무라 초안의 근거가 없다.
- 통합 시 사번이 없거나 충돌한다.
- 유니버스의 입력이 중단되어 이력이 이어지지 않는다(조직관리 유니버스의 입력 중단 포함).
- 심사 환경에서 산출물이 예상대로 실행되지 않는다.

## 10. 비기능 제약

- 개발자 1명, 비개발자 조력자 3명. 코딩은 Claude Max로 수행. 일일 개발 가능 시간 미정(날짜·공수는 적지 않음).
- 기한 10월 30일(1차 제출 기한인지 최종 완료 기한인지 미확인).
- 사내망·보안 제약으로 가상 데이터만 사용.
- 시연 앱이 사용할 LLM은 미확정(사용 불가 또는 확인되지 않은 사내 LLM 가능성).
- 인력 배치 등 조력자 활용 제안: 가상 데이터 작성, 시나리오 사용성 검토, 소개자료·영상 준비.

## 11. 미확인 항목

- 1차 제출물에 요구되는 구현 수준(주최 측 재확인 필요)
- 10월 30일이 1차 제출 기한인지 최종 완료 기한인지
- 심사자가 산출물을 직접 실행하는지 영상 위주인지
- 사내 LLM의 존재와 접근 가능 여부
- 코딩 난이도 평가 방식
- 일일 개발 가능 시간
- 상위 유니버스 통합을 별도 유니버스가 수행하는 구조의 적용 가능성(데이터 모델 단계에서 가상 사례로 검증)

## 12. 승인된 결정

1. v0.2 변경 사항 전체 승인.
2. 조직관리 유니버스는 일반 유니버스(A 수준)로만 시연하고, 기준 데이터 검증 역할은 R-09 문서로만 다룬다.
3. 1차 제출물의 구현 수준이 확인되면 R-ID 우선순위를 재검토한다.
4. LLM 사용 가능 여부가 확인되기 전에는 R-04를 필수로 유지한다.
5. 미확인 항목은 가정으로 표시한 채 데이터 모델 단계로 진행한다.

## 13. 다음 단계 입력

범용 데이터 모델 설계에서 다룰 내용: 유니버스·노드·연결·이벤트의 개념 정의, 사번 기반 사람 연결, 업무 후보 연결(사람 확인), 통합 유니버스 구조와 상위 유니버스의 꼭지 참조, 이력·삭제 규칙, 민감도. 서로 다른 성격의 사례 2개 이상과 예외(변경·누락·중복)를 가상 데이터로 검증한다.
